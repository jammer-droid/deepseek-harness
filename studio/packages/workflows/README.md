# 워크플로 초안

`@local/dsh-studio-workflows`는 프로필별 여러 초안과 초안마다 임의 역할 목록과 메인 역할 참조를 보관한다. Studio 기능 화면에서 새 초안을 만들고 지침을 추가한 뒤 명시적으로 저장한다. 초안 저장은 프리셋 적용·활성화·에이전트 실행과 무관하다. 기존 고정 역할 편집기는 변경하지 않는다.

## 저장과 복구

초안 ID는 클라이언트가 생성하며 최초 저장의 예상 revision은 0이다. 이후에는 읽은 revision을 보내야 한다. 다른 초안의 저장은 해당 revision을 변경하지 않는다. 충돌하면 편집 내용을 유지하고 저장을 차단한다. 다시 읽기는 폐기 확인 후 저장된 내용으로 교체한다.

통신 실패로 저장 결과가 불명확하면 생성·전환·저장을 중단한다. 같은 ID를 다시 읽어 저장 여부를 확인하며 자동으로 재생성하지 않는다. 조회는 접수된 쓰기를 기다린다. 더 최신 revision이 확인되지 않으면 지연된 요청의 가능성이 남으므로 편집 내용과 차단을 유지한다. 저장소 쓰기 실패는 해당 owner의 이후 쓰기와 조회를 차단한다. 플러그인을 다시 시작하여 저장소를 열고 확인된 상태를 읽어야 한다. 해제는 수락한 쓰기를 기다린 뒤 저장소를 닫는다.

## 공개 서비스

Host의 `studioWorkflows.register(definition, validator?)`와 `registerSystem(definition, validator?)`은 `ctx.effect()`에 연결할 해제 함수를 반환한다. 컴포넌트와 시스템의 등록 ID 공간은 구분되며 중복 ID·필드·포트, 잘못된 버전·범위·연결 수 선언은 등록 시 거절한다. 필요한 시스템은 정확한 등록 버전과 같은 워크플로우의 해당 시스템 인스턴스가 모두 있어야 충족된다. 등록되지 않은 의존 대상의 선언 자체는 허용한다.

`components()`, `catalog()`, `models()`, `validate(document)`, `drafts()`, `save(request)`를 Remote에 노출한다. `catalog()`는 분리된 선언과 증가하는 revision을 반환하며 등록 추가·해제와 LLM 제공자 변경마다 `studio-workflows/catalog-changed` Cordis 이벤트를 보낸다. `remoteEventContributions`의 effect 소유 등록이 기존 애플리케이션 Remote source를 통해 Client에 전달하며 별도 Gateway source를 만들지 않는다. Host와 Remote의 비동기 `validate()`는 같은 검증기를 사용한다. 검증 도중 카탈로그가 변경되면 성공을 반환하지 않는다. 결과는 `catalogRevision`, `valid`, 위치·관련 ID·현지화 값을 갖는 `diagnostics`이며 실행 허가가 아니다. 순수 동기 Host 의미 검증기는 복사된 입력을 받고 같은 진단 형식을 반환한다. 함수는 Client 카탈로그에 포함되지 않는다. 저장 실패는 `studio-workflows/rejected` 코드와 `reason`으로 분류한다.

새 문서는 `documentVersion: 3`, 역할 ID와 역할별 컴포넌트·모델, 메인 역할 ID, 워크플로우 소유 시스템, 방향 연결을 보관한다. 인스턴스·연결 ID는 등록 ID와 별개이며 재정렬·이름 변경으로 바뀌지 않는다. 삭제 후 남은 연결도 보존하여 누락 진단으로 표시한다. 시스템 실행 위치는 명시적으로 저장하며 현재 `dsh`만 지원한다. 다른 위치를 자동 대체하지 않는다. 포트 방향은 출력→입력이고 의미 ID는 정확히 일치해야 하며 양쪽 `allowedPeers`에 상대 등록 ID가 있어야 한다. 빈 허용 목록은 아무 상대도 허용하지 않는다. 텍스트 필드의 `required`는 존재 여부를 검사하며 빈 문자열은 허용한다.

저장은 문서 형식만 검사한다. 잘못된 조합·설정 필드 타입·미지원 위치도 유효한 JSON 문서이면 저장할 수 있으며 구성 검증은 별도 요청이다. 저장 domain 버전은 1을 유지하며 legacy 문서는 draft ID와 원래 컴포넌트 위치에서 결정적인 인스턴스 ID를 생성하고 빈 시스템·연결 배열을 부여한다. legacy와 v2의 메인 역할은 draft ID에서 생성한 역할 ID로 옮기고 기존 인스턴스·연결·설정을 보존한다. 모델은 미선택으로 둔다. 읽기는 저장소를 다시 쓰거나 revision을 바꾸지 않는다. 다음 명시적 저장은 기존 revision을 비교한 뒤 새 문서를 기록한다. 손상된 문서는 빈 초안으로 대체하지 않는다. 새 형식을 이전 코드로 읽는 downgrade는 지원하지 않는다.

문서는 컴포넌트 ID·버전·JSON 설정을 보관한다. 사용할 수 없는 컴포넌트나 버전도 저장·재열기 시 보존하며 실행 가능하다고 해석하지 않는다. 역할을 삭제해도 메인 참조와 연결을 자동 대체하지 않으며 누락 진단을 표시한다. 초안 삭제·복제, 템플릿과 프리셋 적용은 현재 범위가 아니다.

## 모델과 추론

`models()`는 DSH `listProviders`, `listModels`, `resolveModelInfo`에서 모델별 추론 옵션과 공개된 기본값을 읽는다. 목록에 없는 모델은 코어가 라우팅할 수 있어도 Studio에서는 거절하며 `resolveCallConfig`로 추론 지원을 확인한다. 모델·추론이 미지원이 되어도 선택값은 보존한다. 조회 실패는 미지원 판정과 구분하며 다른 모델로 바꾸지 않는다. 모델 서비스가 없는 프로필도 초안을 저장할 수 있지만 지원 검증은 성공하지 않는다. 실패한 제공자나 메타데이터는 카탈로그 상태와 구조화 실패 값으로 전달하고, 검증은 역할 ID와 필드에 연결된 진단을 반환한다. 호출자는 재조회 전까지 실패한 항목의 지원을 신뢰하지 않는다.

최초 모델 선택은 현재 역할들과 이후 추가 역할의 초기값으로 독립 복사한다. 역할별 편집은 다른 역할과 초기값을 바꾸지 않는다. 추론 미지정은 해당 모델의 제공자 기본값이며 메인 역할이나 다른 역할을 상속하지 않는다. 초안 검증은 인증·모델 요청 성공·실행 권한을 보장하지 않는다.

## 검증

저장소·Loader·UI 검증은 [Studio 테스트](../../test/)의 `workflow-*.test.mjs`가 소유한다. 브라우저 수용 검증은 [초안 편집 테스트](../../test/workflow-editor.browser.test.ts)가 격리된 프로필에서 수행한다. 설치된 사용자 프로필에 배포하거나 실행 설정을 변경하는 테스트가 아니다.
