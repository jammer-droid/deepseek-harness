# #24 minimal 기반 프리셋 구성과 선택적 덮어쓰기

## 2026-10-18 Master 수명 정리 (구조 개선 R2)

기존 기능·실패 동작을 유지하는 내부 리팩터링. [#31의 R1](31-pixie-loop.md) 다음에 수행하고 R3 전에 양측 교차 리뷰한다. `MasterCatalog`가 현재 snapshot, 직렬 변경 큐, 등록 disposer, stopped, standard, 확장 파일, baseline/pending과 capture/observe/confirm을 함께 소유한다. Shell은 기존 Remote 서명, PresetStore, 플러그인·스킬 설치와 effect 순서를 유지한다.

- 초기 수집은 기존 위치에서 `setImmediate` 이후 시작한다. 각 reader는 호출 시점의 snapshot을 기다린다.
- 교체 순서: 이전 작업 종료 → snapshot → 이전 확장 읽기 → 임시 probe 등록·resolve·해제 → 기존 Master 해제 → 새 capture → 확장 저장.
- 실패 시 disposer를 다시 호출하고 이전 구성을 capture하여 snapshot을 복구한 뒤 원래 오류를 던진다. 복구 자체가 실패하면 복구 오류가 우선한다. 기존 부수효과를 새 보상 로직으로 바꾸지 않는다.
- 종료는 stopped 표시 → 현재 snapshot의 성공/실패 대기 → disposer 호출이다. 변경 큐 전체를 기다리지 않는 기존 제한도 유지한다.
- 검증: 이동 전 characterization(실패 probe, 교체 실패/저장 실패, 복구 실패 우선순위, 동시 요청, 초기화/종료), 이동 후 같은 테스트와 Master/Remote/스킬 회귀, Studio 타입·빌드, OpusRev와 Reviewer 독립 검토.
- 상태: 이동 전 characterization 9개 통과 후 추출. 이동 후 start/ready/stop 테스트 포함 수명 테스트 10개, 전체 Studio 테스트 754개, Host/Client 타입·번들 빌드 통과. Reviewer 독립 검토 PASS(당시 Master 관련 23개 독립 실행), OpusRev 읽기 전용 독립 검토 PASS. 등록 Context는 Studio 소유자로 통일했다(이전 Remote 교체는 Gateway 호출 Context). 검토한 registry는 이 Context에서 baseUrl만 사용하고 검증된 bare package 이름은 loader의 bare-module 경로로 해석하므로 현재 지원 입력의 관찰 가능한 차이는 예상하지 않는다. 향후 상대 경로 입력을 허용하면 이 전제를 재검토해야 한다. 전체 테스트는 Studio 디렉터리에서 실행해야 한다(루트에서 실행한 최초 시도는 기존 plugin-catalog 테스트의 상대 경로 때문에 실패). 순정 DSH 설치 검증은 별도이며 아직 수행하지 않았다.

## 최신 UI 수정 계약 (기존 S1–S5 내보내기/단일열 결정을 대체)

- 기본 4개 프리셋의 비도구 기여자는 7종: persona, agent-instructions, time-context, skill-filesystem, compaction-basic, compaction-tool-result-pruner, agent-tool-presentation.
- 공개 설정은 상세에서 속성별 편집한다. persona 및 jobs 독립 편집기를 제거하고 도구 설명·중첩 인자 설명·관련 지침을 상세에 통합한다.
- 기본 선택 도구 없음, 모델 testLLM 고정, 내보내기 UI와 RPC 제거. 과거 export 구현/검증 기록은 현재 기능 약속이 아니다.
- 좌측 섹션명/우측 본문, 아래 도구 스키마. 실제 assemble override 사용. 선택 해제한 항목의 override는 전송하지 않는다.
- 정적 미리보기에서 pre-step 메시지/압축은 실행하지 않는다. 압축 modelPolicies 표, 도구 타입/필수 여부 변경, 모든 동적 지침 교체는 미지원이다.
- 기존 roles-ui.expected.html은 현재 트리에 존재하지 않아 재생성할 수 없다. 현재 디자인 테스트와 UI 회귀 테스트로 검사한다.

### 최신 검증 결과

- Studio 타입 검사·빌드·23개 테스트 및 diff 공백 검사 통과.
- 수정하지 않은 DSH 0.2.0-rc.2 격리 프로필에 재설치하여 실제 RPC의 provider 단독 mount, persona/도구/인자/섹션 override, 원본 복귀, 정확한 도구 선택, 임시 프리셋 정리를 확인했다.

- PTC 모드는 run_code를 자동 생성해 정확한 선택 정책에서 거부된다. native 설정은 검증했다. UI에 제한을 표시한다.
- 최초 실환경 검사에서 compaction 제거 후 command-compact 의존성이 남는 오류를 발견해 종속 command도 함께 제거하도록 수정했다.
- 설치 중 peer dependency 경고가 있었고 실제 RPC는 통과했다. 시각 검증과 라이브 모델 호출은 수행하지 않았다.

## 목표와 확정된 사용자 결정

최종 산출물은 minimal을 출발점으로 구성한 Studio 소유 프리셋과 필요한 정책 플러그인·의존성 정보다. 사용자는 도구 및 DSH 프롬프트 제공 플러그인을 선택하고, 필요한 지침·설명·공개 설정만 편집한다.

1. 원본 minimal을 변경하지 않고 복사본을 구성한다. persona 문구를 편집할 수 있으며 복사본에서 `complete: false`를 사용한다.
2. 기본 shell도 고정하지 않고 선택 가능한 구성으로 취급한다. persistent bash와 일반 bash는 이름만 보고 동일한 구현으로 간주하지 않는다.
3. 도구는 Studio가 실행 중인 DSH 런타임에서 감지한다. 다른 Desktop/격리 서버의 도구를 자동으로 공유한다고 표시하지 않는다.
4. 프롬프트 제공자는 특정 프리셋에 한정하지 않고 사용 가능한 프리셋의 플러그인 구성을 모아 제시한다. 도구와 제공자 각각 투 컬럼 선택 UI를 사용한다.
5. DSH 환경 자동 주입 항목은 선택 목록에서 제외하되 실제 조립 미리보기에는 유지한다.
6. persona 등 공개 설정으로 편집 가능한 영역을 제공한다. 도구 설명·인자 설명·도구 관련 시스템 섹션은 지원되는 scope에서 원본을 가리는 등록으로 덮는다.
7. 수정하지 않은 필드는 원본을 유지한다. 원본 사용으로 복귀하면 override를 제거한다. 전역 원본 객체나 플러그인 파일을 변이하지 않는다.
8. 추가 작성한 지침은 최하단 `studio:additional` 섹션으로 제공한다. 완성된 프롬프트를 매번 통째로 교체하지 않는다.

## 개념과 경계

- **플러그인**: 도구나 프롬프트 기여를 등록하는 구성 단위.
- **도구 정의**: 모델에 보이는 이름·설명·인자 스키마와 내부 실행 콜백의 등록 단위.
- **시스템 섹션**: 조립된 본문의 구성 단위. 플러그인과 일대일 관계가 아니다.
- **덮어쓰기**: 원본 유지 상태에서 Studio 소유 scope/구성에 차이만 적용하는 것. 도구 숨김이나 권한 변경과는 구분한다.
- **원본 사용**: 저장된 차이를 제거해 다시 상속하는 것. 빈 문자열로 편집한 상태와 다르다.

공개 API로 확인 가능한 출처만 표시한다. 섹션 이름을 플러그인 이름으로 취급하거나 임의로 연결하지 않는다. 전역 제공 도구와 프리셋 내부 제공 도구를 구분하고 같은 scope에 중복 등록하지 않는다. 공개 설정이 없는 플러그인의 내부 상태·코드를 편집하지 않는다.

## 화면 계약

- 도구·프롬프트 제공자: 각각 사용 가능/선택됨의 투 컬럼 선택.
- 카드: 체크박스 없이 선택 음영, 일정한 높이, 긴 설명 요약. 선택과 독립된 상세 버튼 제공. 키보드 조작과 선택 상태의 접근성 의미는 유지한다.
- 상세: 원본 값과 사용자 변경 여부, 지원하는 설정, 원본 사용 동작을 제공한다. 도구의 타입·필수 여부·실행 구현을 설명 편집으로 변경하지 않는다.
- 미리보기: 조립 순서와 내용을 하나의 레이아웃·스크롤 영역으로 묶는다.
- 전체 시스템 프롬프트 원문 및 런타임 컨텍스트 전용 패널은 제거한다. 런타임 컨텍스트의 실제 주입을 제거하는 변경은 아니다.
- 도구 스키마: raw JSON 대신 이름·설명·인자 타입·필수 여부·설명·제약을 구조화하여 접고 펼친다.
- 프롬프트 제공자가 pre-step 메시지를 주입하는 경우 시스템 섹션으로 위장하지 않는다. 모델 호출 없는 미리보기의 지원 범위와 누락 이유를 표시한다.
- UI 문구는 ko/en/zh 사전과 기존 Studio 디자인 시스템을 따른다. 사용자에게 시각 확인을 맡긴다는 기존 요청을 유지하며 수행한 기술 검증과 구분한다.

## 현재 근거와 제약

- [minimal 구성](../../../../packages/bundle/web-app/presets/minimal.patch.yml)은 persona `complete: true`, `includeRuntimeContext: false`와 persistent shell 구성을 포함한다. complete 설정을 그대로 두면 추가 시스템 섹션이 숨겨진다. includeRuntimeContext는 별도 사용자 변경 없이 유지한다.
- 현재 Tools 공개 계약에는 `get`, `schemas`, `register`, `restrict`가 있으며 필드 전용 patch 메서드는 없다. 도구 정의의 설명을 바꾸려면 실행·검증·프레젠테이션 관련 속성을 유지한 별도 정의 등록이 필요하다.
- scoped 등록은 상위 정의를 가리지만 같은 layer의 중복 등록은 실패한다. scoped 도구는 전역 도구용 restrict와 동일하게 취급되지 않으므로 설명 편집으로 제외된 도구가 재노출되지 않게 해야 한다.
- 현재 Studio 카탈로그는 실행 서버 기준이다. 설치되지 않은 구독 플러그인의 video 도구 등을 수동 목록만으로 실행 가능하게 만들 수 없다.
- 기존 최적화는 bash/job_output 설명 수정, tool:jobs 본문 교체, headless-policy 신규 지침 추가였다. Goal/Todo 제외는 별도 도구 선택 정책으로 취급하며 자동으로 함께 적용하지 않는다.
- 이 문서는 정책 편집 기능 명세이며 최적화 문구를 기본 활성화하거나 자동 적용한다는 의미가 아니다.

## 소유권과 불변 조건

- 초안에는 선택 항목과 원본 대비 override를 분리하여 보존한다. 저장·내보내기 포맷과 버전은 S1에서 정한다.
- 미리보기와 실제 프리셋은 동일한 구성 변환 경로를 사용한다. 미리보기 전용 문자열 삭제로 실제 동작을 꾸미지 않는다.
- scoped 등록의 disposer를 Studio 플러그인과 해당 scope 수명에 연결한다. 종료·해제·실패 시 임시 preset/lease/등록이 남지 않아야 한다.
- 등록 객체의 직접 변이나 비공개 필드 의존은 금지한다. 정책 편집이 도구 실행 함수·타입·권한·검증·표시 콜백을 변경하지 않아야 한다.
- 원본 갱신/플러그인 해제 시 오래된 정의를 조용히 사용하지 않는다. 적용 시 검증과 실패 표시 정책을 S1에서 확정한다.
- 다른 환경에서 의존성이 누락된 경우 누락을 명시하고 적용을 차단한다. 원본 플러그인을 자동 설치하거나 사용자 프로필을 무단 변경하지 않는다.

## 구현 단계

### S1 — 공개 API와 구성 계약 확정 (첫 단계)

- 선행: 없음. 정확한 미수정 DSH 버전, 작업 기준 코드 확인.
- 책임: 카탈로그 출처, 도구 제공 플러그인 구성, prompt provider와 섹션 대응, scoped 등록 시점·계층, 저장/내보내기 포맷.
- 수용: global/preset/scoped 도구와 자동 주입 항목을 구분하고 미지원 항목은 명시한다. preset 내부 도구도 중복 없이 override 가능한지 검증한다.
- 검증: 공개 API 조회와 작은 격리 runtime 계약 테스트. 등록→조립→해제, complete:false, 도구 제외 후 override 비노출 확인.
- 공개 API가 부족하면 코어를 수정하지 않고 제약과 Studio 내부 대안을 제시한다.

### S2 — 초안 모델·카탈로그·선택적 정책

- 선행: S1.
- 책임: 런타임 도구/제공자 카탈로그, minimal 복사 구성, override 저장 및 복귀, persona 편집, 정책 등록·해제.
- 수용: 미편집 필드와 실행 콜백 보존, 설정 오류 표시, 선택과 권한 일치, 등록 실패 시 정리. 플러그인 설정은 공개 schema로 검증한다.
- 검증: 상속/빈값/원복, 중복 등록, 제한 도구, 누락 의존성, disposer·실패 회귀 테스트.

### S3 — 투 컬럼 선택과 상세 편집 UI

- 선행: S2.
- 책임: 두 선택 목록, 고정 높이 카드, 선택 음영, 별도 상세 버튼, 설정 편집·원본 사용.
- 수용: 상세 열기가 선택을 토글하지 않고 키보드·좁은 폭에서 사용 가능. 선택 불가/편집 불가 사유와 실제 런타임 출처를 표시한다.
- 검증: 선택/상세 상호작용 및 locale 테스트, Studio UI 스냅샷과 타입 검사. 시각 확인은 사용자 확인과 구분한다.

### S4 — 조립 미리보기 통합

- 선행: S2, S3.
- 책임: 단일 스크롤 조립 레이아웃, 불필요 패널 제거, 구조화된 접이식 도구 schema.
- 수용: 실제 assembler 결과 유지, Studio 추가 지침 최하단, 도구 스키마와 본문 구분. 동적 메시지의 미리보기 한계를 명시한다.
- 검증: 순서/누락/빈 도구 선택/에러 정리/중첩 인자 제약 표시 테스트. 실제 프리셋 경로와 결과 비교.

### S5 — 프리셋 산출물과 독립 설치 검증

- 선행: S2–S4.
- 책임: 프리셋·정책 플러그인 연결 및 의존성 명시, 사용자 문서, 격리 설치 검증.
- 수용: 수정하지 않은 고정 버전 DSH에서 산출물을 로드하고 조립·도구 노출·원본 복귀를 검증한다. Studio 밖의 변경 없이 동작한다.
- 검증: Studio 테스트·타입 검사·빌드·scope 검사와 패키징 후 격리 설치. 런타임 버전·실행 경로·패키지·명령·결과 기록. 라이브 모델 호출 여부는 별도 기록한다.

## S1–S5 구현 및 검증 기록

사용자의 S5까지 진행 승인으로 아래 범위를 구현했다. 전체 제품 요구가 제한 없이 완료되었다는 뜻은 아니다.

- **S1:** 미수정 DSH `0.2.0-rc.2`를 배포 검증 대상으로 고정했다. 하위 scope restrict는 상위 scoped 도구도 숨긴다. 같은 layer 등록만 예외이며 초기 초과 도구는 오류, 나중에 추가되는 미선택 도구는 guard로 실행 차단한다.
- **S2:** minimal persona 복사, complete:false, 세 종류 제공자 수집, 공개 설정 allowlist, 설명·인자·섹션 override, disposer를 구현했다. 도구가 전역에 없으면 minimal 우선으로 하나의 호환 원본 composition을 선택한다. 서로 다른 preset scope의 live 실행 함수를 이식하지 않는다. 모든 선택 도구를 공급하는 단일 구성이 없으면 명시적으로 거부한다.
- **S3:** 투 컬럼, 고정 높이 음영 카드, 독립 상세 버튼, persona·공개 제공자 설정·도구 설명·인자 설명·jobs 지침 편집 및 원본 복귀를 구현했다. ko/en/zh 문구와 상호작용 테스트를 추가했다.
- **S4:** 실제 조립 순서와 본문을 한 스크롤로 표시하며 raw 전체 prompt/runtime 전용 패널을 제거했다. 도구 schema는 구조화된 접이식 표시로 바꿨다. 추가 지침 최하단과 빈 도구 선택을 검증했다.
- **S5:** package/patch/한국어 안내문 내보내기, 별도 policy export, Loader `!!js` 보존, 공개 RPC를 구현했다. 패키징 설치 및 내보낸 preset의 새 세션 생성까지 확인했다.

### 남은 제한 및 미검증

- 제공자 탐색은 모든 프리셋을 순회하지만 persona/agent-instructions/time-context의 명시적 지원 목록이다. 임의 제3자 Config 자동 편집은 지원하지 않는다.
- 동명 도구 구현을 선택하는 출처 UI는 없다. 전역 구현 우선이며, incompatible preset 조합은 차단한다.
- UI 인자 편집은 최상위 속성만 제공한다. 정책 엔진은 dotted 중첩 속성도 검증할 수 있다. 원본 복귀는 도구/제공자 단위다.
- 초안은 메모리 상태이며 영구 저장·재불러오기 미구현이다. 내보내기는 여러 파일 다운로드이므로 브라우저 허용이 필요하다.
- shell 패키지는 공개 registry에 배포하지 않았다. 다른 머신 설치에는 shell tarball/접근 가능한 registry 및 해당 원본 provider 의존성이 필요하다.
- sessionless 미리보기 cwd는 서버 작업 디렉터리다. pre-step instructions/time 메시지, 실제 세션의 동적 컨텍스트, 모델 실행 결과까지 재현하지 않는다.
- 내보낸 preset의 새 Agent 생성은 확인했으나 해당 Agent의 실도구 실행·모델 호출까지 검증하지 않았다. UI 시각·좁은 화면 확인은 사용자에게 맡긴다.
- 푸시·병합·이슈 종료는 수행하지 않는다.

사용법과 배포 조건은 [프리셋 내보내기 안내](../reference/preset-composition.md)를 참고한다.
