# #15 지침 컴포넌트 초안 편집·저장

## 요약

대상은 [GitHub #15](https://github.com/jammer-droid/deepseek-harness/issues/15)이다. 구현 상태는 `completed`이며 S1–S4의 등록·편집·다중 초안 저장·실패 복구·수용 검증을 완료하고 `studio-general`에 로컬 통합했다. 선행 이슈는 없다. [구조 검토](../archive/workflow/workflow-architecture-review.md)와 [작업 절차](../design-workflow.md)를 따른다.

작업 브랜치는 `studio/workflow-15-draft`, 통합 대상은 `studio-general`이다. 분기점은 워크플로우 기획 문서를 추가한 커밋이며 작업 절차 설정도 이 브랜치에 포함한다. 이슈 완료·검증 후 로컬 통합은 승인되었고 푸시는 승인 범위에 포함하지 않는다. 원래 worktree의 디자인 변경은 보존한다.

## 결과와 범위

사용자는 메인 역할에 등록된 지침 컴포넌트를 추가·편집하고 초안을 저장·다시 연다. 저장이 실제 프리셋과 실행 구성을 변경하지 않는 것이 핵심 불변 조건이다. 기존 General과 고정 역할 편집기는 공존한다.

모델·임의 역할 편집, 시스템 연결의 전체 의미 검증, 실제 프리셋 적용, 자식 실행, 템플릿 복사는 후속 이슈 범위다. 등록과 문서 저장 구조가 후속 확장을 막지 않아야 하지만 이 작업에서 미래 실행 interface를 확정하지 않는다.

## 현재 근거

[역할 설정 소유자](../../packages/roles/src/roles.ts)는 프로필 키의 storage domain, 직렬화된 쓰기, 관찰된 리비전 검사와 자식 설정 캡처를 제공한다. 그러나 저장이 활성화와 결합되어 있고 모델 검증 및 고정 역할 쌍에 의존하므로 초안 저장 API로 재사용하지 않는다. 저장·충돌 처리의 패턴만 참고하고 새 초안의 상태 소유권을 분리한다.

[Studio 개발 안내](../../development.ko.md)에 따라 Host 상태는 공개 서비스와 Remote를 통해 접근하고 UI 문구는 locale 소유다. 디자인 목업과 공존하며 실제 초안 편집기는 기존 features Slot을 통해 ‘역할·실험 기능’에서 제공한다. 목업은 실행 기능으로 대체하지 않는다.

## 확정된 조건

- 등록은 효과 수명에 묶고 해제 가능한 소유권을 가진다.
- 지침 정의의 안정적 ID·설정 정의·적용 범위를 검증하며 편집 UI가 동일한 정의를 사용한다.
- 초안은 저장 가능한 문서와 실행 가능한 구성을 구분한다. 미해석 설정은 보존한다.
- 저장 충돌은 덮어쓰기 없이 표시하며 읽기·저장 실패 시 확인되지 않은 성공을 표시하지 않는다.
- 기존 데이터와 프리셋을 자동 변환하거나 변경하지 않는다.

## 초안 저장 범위

프로필별 여러 워크플로우 초안을 안정적인 ID로 보관하고 최소 목록·생성·선택을 제공한다. 역할은 초안마다 메인 하나로 제한한다. 초안 삭제·복제·이름 있는 설정 템플릿은 후속으로 미룬다. 선택 전환 시 미저장 편집을 조용히 잃지 않도록 확인하며, 생성 실패나 응답 유실을 성공으로 표시하지 않는다.

## 완료한 구현 단계

| ID | 결과 | 선행 | 수용 및 검증 |
|---|---|---|---|
| S1 | 등록된 지침과 메인 역할을 Host와 UI에서 조회·편집 | 없음 | 동일 등록 정의로 기본 UI 표시, 잘못된 등록 거절, 효과 해제, 실제 Loader 구성 |
| S2 | 초안 저장·재열기와 저장 상태 표시 | S1 | 실제 storage domain 및 Remote 왕복, 프리셋 무변경, 재열기 보존, 사용자 출력 스냅샷 |
| S3 | 충돌·읽기·저장 실패의 안전한 재조회 | S2 | 동시 편집 충돌, 미해석 설정 왕복, 실패 후 거짓 성공 없음, UI 실패·재시도 흐름 |
| S4 | 수용 검증과 제품 문서 반영 | S3 | 키 없는 Host·브라우저 검증, 기존 기능 공존, 영향별 검사 결과 기록 |

첫 단계는 S1이다. 기능은 별도 Studio workflows Host/Client 패키지가 소유하고 기존 features Slot에 편집기를 등록한다. 지침 등록은 Host registry가 소유하며 Remote가 직렬화 가능한 설정 정의를 전달한다. 일반 플러그인 설정 행에서 기능을 추론하지 않는다. S1은 등록·편집을 다루며 영속 저장은 S2에서 연결한다.

S2는 공개 `storageDomain.open()`으로 전용 domain을 열고 프로필별 초안 컬렉션을 보관한다. 저장 owner가 쓰기를 직렬화하고 해제 시 수락한 쓰기를 drain한 뒤 domain을 닫는다. 각 초안의 안정적 ID와 저장 revision을 비교하여 다른 초안의 편집을 불필요하게 충돌시키지 않는다. wire·영속 입력을 검증하고 알려지지 않은 컴포넌트의 JSON 설정을 보존한다. 생성 요청은 클라이언트가 유지하는 ID로 재조회할 수 있게 하여 응답 유실 후 중복 생성하지 않는다.

S3는 저장 충돌·유효하지 않은 요청·서비스 종료와 저장 결과 불명을 구조화된 실패로 구분한다. 저장 실패 후 실제 상태 안전성을 확정할 수 없으면 쓰기를 중단하고 재시작·재조회로 복구한다. UI는 편집 내용을 유지하며 최신 저장 내용을 확인하기 전 자동 재시도하지 않는다. 이슈 #16의 전체 시스템 연결 의미 검증은 도입하지 않는다.

단계별 테스트는 등록 ID 중복과 해제, UI 입력·전환, 실제 domain 재열기·프로필 격리·동시 저장, 장애 주입과 눈에 보이는 오류를 검증한다. 기존 Typert 생성기를 workflows 패키지에도 적용하고 실제 Loader 테스트에서 서비스 조회·해제를 확인한다. S4는 기존 Studio 회귀와 변경 출력 스냅샷을 실행하고 설치된 앱 검증과 격리 테스트를 구분한다.

## 검증 기록

격리 worktree에서 `pnpm install --frozen-lockfile`과 `pnpm --dir studio run prepare:types`가 종료 코드 0으로 완료되었다. `node --import tsx --test studio/test/workflow-registry.test.mjs`의 두 테스트가 통과했다. 등록 중복·잘못된 정의·분리된 조회 결과·해제 후 재등록의 소유권을 확인했다. S1에서 Studio build(Host·Client 타입 검사 포함) 및 등록·실제 Loader/Gateway·UI 집중 테스트 4개가 통과했다. Loader 테스트는 역할·모델·프리셋 서비스 없이 등록 조회와 해제 후 unavailable을 확인한다. UI 테스트는 하나의 메인 역할과 등록된 지침 편집, locale 변경 시 입력 보존, 등록 부재 안내를 확인한다. S2·S3에서는 실제 domain의 프로필 격리·재열기·리비전 충돌, 저장 장애 이후 대기 쓰기 차단과 재시작 복구, 해제 시 쓰기 drain, 미해석 JSON 보존을 검증했다(저장소 테스트 5개). UI의 생성·저장·선택·폐기 확인, 충돌 시 편집 유지와 명시적 재조회, 생성 응답 유실 이후 동일 ID 확인, 출력 스냅샷을 검증했다(UI 테스트 4개). 최종 검토에서 접수된 쓰기 이후의 재조회와 선택 입력 필드 검증을 보완했다. 결과 불명의 저장은 부재·이전 revision만으로 성공이나 미저장을 확정하지 않는다. 보완 후 집중 테스트 14개가 통과했다. Studio build·타입 검사 및 번들 pack이 성공했다. Chrome 격리 scaffold 브라우저 테스트는 두 초안의 생성·지침 저장·페이지 새로고침·각 초안 재선택과 지침 복원을 통과했다. 저장된 텍스트가 접근성 이름에 섞이지 않도록 선택기와 지침 입력에 명시적 locale 이름을 부여했다. 설치된 사용자 프로필은 변경하지 않았으며 설치된 제품 GUI 검증과 구버전 Desktop 호환 빌드는 수행하지 않았다. 기준 브랜치에 추가된 디자인 커밋을 보존하는 로컬 merge 방식은 사용자가 별도로 승인했다.

초안 구현과 디자인 작업을 함께 로컬 통합했으며 기존 디자인 변경을 보존했다. 통합 후 frozen-lockfile 설치와 Studio build·타입 검사가 통과했다. 공용 Button 출력 스냅샷을 갱신한 뒤 UI 테스트가 통과했다.

## 완료 결과

초안 저장은 실행 프리셋을 변경하지 않는다. Preset Builder 상단 서비스의 Workflow 좌측 메뉴에서 초안을 편집·저장·재조회한다. 서비스 등록 구조와 미저장 입력 보존은 [서비스 탐색 구조](../reference/service-navigation.md)에 기록한다. 실제 프리셋 적용·활성화·실행은 이번 이슈 범위 밖이다.

Studio Node 회귀 63개, 실제 Loader·저장 장애 주입·UI 출력 테스트, 격리 Chrome의 Workflow·역할 편집·전체 실행 시나리오가 통과했다. Preset Builder 변경 후 빌드, 관련 단위 테스트 6개와 Workflow 브라우저 테스트도 통과했다. 서비스 순서·기본 선택·미저장 입력 보존·라이트와 다크의 720px 메뉴 전환을 검증했다. 라이브 모델 검증이나 설치 프로필 배포를 대신하는 증거로 간주하지 않는다. 사용자는 Web에서 변경을 확인하고 이슈 종료와 커밋·로컬 통합·원격 푸시를 승인했다.
