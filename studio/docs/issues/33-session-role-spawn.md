# #33 세션 역할의 시작 방식 편집

## 목적과 범위

[GitHub #33](https://github.com/jammer-droid/deepseek-harness/issues/33)의 목표는 Subagents 탭에서 프리셋 역할의 세션 복사본과 임시 역할의 시작 방식(Fresh/Fork)을 선택하는 것이다. 선행 [#29](29-session-roles.md)는 GitHub에서 CLOSED다. 기준 브랜치는 `studio/feat/workflow`이며, 작업 시작점은 `refactor(studio): isolate recording and Master lifecycles` 통합 직후의 clean 상태다.

세션 역할 입력·검증, 추가·편집 폼, ko·en·zh 안내, 단위·DOM·실행 회귀 검사와 독립 설치 확인을 포함한다. 도구 필터 편집, 프리셋 변경, 기존 자식 재설정, DSH 코어 변경, 캐시 최적화는 제외한다. 설치된 사용자 앱·프로필 변경과 푸시·이슈 종료는 별도 승인 대상이다.

## 현재 근거

- [session-roles.ts](../../src/session-roles.ts)는 수정 필드를 `model`·`reasoning`·`persona`로 제한하고 신규 역할의 `spawn`을 `fresh`로 고정한다. 저장 레코드에는 이미 `spawn`이 있으므로 새 저장 형식이 필요하지 않다.
- [session-roles-tab.tsx](../../src/session-roles-tab.tsx)는 시작 방식을 표시하지만 편집 필드를 제공하지 않는다. [role-editor.tsx](../../src/role-editor.tsx)의 프리셋 편집은 이미 시작 방식 선택을 제공한다.
- [role-tool.ts](../../src/host/role-tool.ts)는 호출마다 역할을 읽고 `spawn`에 따라 DSH의 `spawn` 또는 `fork` provider를 선택한다. 모델 옵션은 두 경로 모두 전달한다.
- #29 D6의 고정 정책을 이번 이슈에서 확장한다. 시작 방식은 세션에서 편집할 수 있으며 도구 필터 제한은 유지한다.

## 확정 계약

- **D1 입력:** `SessionRolePatch`에 `spawn`을 추가한다. 허용 값은 `fresh`·`fork`뿐이며, 그 외 값은 저장 전에 거절한다. 신규 입력에서 생략하면 `fresh`, 수정에서 생략하면 기존 값 유지다. 기존 호출자와 저장 레코드는 계속 유효하다.
- **D2 소유권:** 프리셋 역할 첫 수정은 기존처럼 역할 전체를 세션에 복사한다. 이후 시작 방식도 그 복사본이 소유하며 프리셋 자체는 수정하지 않는다. 되돌리기는 복사본을 제거해 현재 프리셋 값을 다시 사용한다. 도구 필터 편집 제한은 유지한다.
- **D3 적용 시점:** 저장 완료 후 시작되는 다음 `subagent_role`의 새 자식 생성부터 반영한다. 이미 시작한 호출과 자식의 설정은 바꾸지 않는다. 기존 자식 id를 이용하는 continuation은 생성 당시 자식의 실행 경로·설정을 유지하며 최신 역할 설정으로 다시 생성하지 않는다.
- **D4 모델:** Fork의 별도 모델 지정도 기존 프리셋 역할과 동일하게 허용하고 기존 저장·호출 시 모델 검증을 유지한다. 대화 이력 상속은 KV 캐시 재사용 보장이 아니다. UI는 Fresh가 새 대화, Fork가 부모 대화 이력을 이어받는다는 점과 변경이 새 자식에만 적용됨을 설명한다. 모델을 변경해도 캐시가 유지된다는 안내는 하지 않는다.
- **D5 UI:** 추가 폼 기본값은 Fresh, 편집 폼 초기값은 현재 역할 값이다. 저장·재조회·카드 표시가 일치해야 한다. 자식 세션의 읽기 전용 규칙, 오류 표시, 모델·추론·지침 필드는 유지한다. 기존 공용 UI 부품과 locale 체계를 사용한다.
- **D6 호환성:** 독립 검증 기준은 사용자가 승인한 현재 설치된 순정 DSH `0.2.1-rc.2`다. 공개 `studioSessionRoles` Remote와 기존 자식 시작 API를 사용하며 코어 API 확장은 없다. 구현 전에 Inspect로 현재 공개 계약을 확인한다. 현재 GUI 런타임 확인은 지정 버전 독립 설치 증거를 대신하지 않는다. 다른 런타임 버전까지의 지원 확대는 이번 이슈에서 주장하지 않는다.

| S1 | 세션 역할 입력·저장 계약 확장 | — | 순수 함수·서비스 테스트: 기본 Fresh, Fork 추가, 양방향 수정, 생략 시 유지, 잘못된 값 거절, 프리셋 불변, 도구 필터 제한, 저장·재조회와 되돌리기 |

S4는 실제 Loader와 자식 실행 경로를 사용한다. 스크립트 응답 모델을 쓰면 그 사실을 기록하고 실제 모델·KV 캐시 성능 검증으로 표현하지 않는다. 설치 준비물이 없거나 공개 API가 부족하면 구체적인 제한을 기록하고 독립 배포 완료로 표시하지 않는다. 사용자 앱을 교체하거나 다른 서버를 현재 GUI로 간주하지 않는다.
