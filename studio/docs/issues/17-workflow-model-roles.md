# #17 DSH 카탈로그 기반 모델·추론 및 임의 역할 편집

## 요약

대상은 [GitHub #17](https://github.com/jammer-droid/deepseek-harness/issues/17)이다. 구현과 S1–S4 검증·리뷰를 완료했다. 아래 전체 테스트 실패 제한을 포함하여 구현 브랜치에 기록한다. 선행 [#16](16-workflow-validation.md)은 GitHub에서 종료됐다. 작업 브랜치는 `studio/issue-17-model-roles`이며 시작점은 분기 시점의 `studio/feat/workflow`다. 별도 worktree에서 구현하며 원래 작업 트리의 명세 변경은 유지한다.

## 범위와 현재 근거

사용자는 임의 역할을 추가·수정·삭제하고 그중 메인 역할을 지정하며, 실제 DSH 카탈로그의 모델과 해당 모델의 추론 옵션을 각 역할에서 독립 편집한다. 저장은 프리셋 적용·활성화·실행과 별개다. 실행 연결은 후속 이슈이며 DSH 코어·기존 General·고정 역할 설정은 변경하지 않는다. 전체 제품 요구는 [기능 명세](../archive/workflow/workflow-specification.md), 책임 분리는 [구조 검토](../archive/workflow/workflow-architecture-review.md)가 소유한다.

현재 [문서 타입](../../packages/workflows/src/workflow-types.ts)은 `documentVersion: 2`와 인라인 `mainRole` 하나를 갖는다. [저장](../../packages/workflows/src/drafts.ts)은 legacy와 v2를 읽고 v2만 쓰며, [검증](../../packages/workflows/src/validation.ts)은 메인 역할의 컴포넌트만 순회한다. [Host 서비스](../../packages/workflows/src/index.ts)는 모델 서비스 없이 마운트된다. [실제 Loader 테스트](../../test/workflow-loader.test.mjs)는 이 독립성과 Gateway 결과를 확인한다.

DSH의 [LLM 서비스](../../../packages/llm/llm/src/index.ts)는 `listProviders`, `listModels`, `resolveModelInfo`, `resolveCallConfig`를 제공한다. 카탈로그 등재는 코어 라우팅 제한이 아니므로 Studio가 선택·검증에서 등재 여부를 별도로 확인해야 한다. 추론 메타데이터는 `listModels`가 아니라 정확한 모델에 대한 `resolveModelInfo`에서 조회한다.

## 선택한 동작

### 역할과 데이터 호환

새 문서는 v3로 구분하고 안정적인 branded 역할 ID, 역할 배열, 메인 역할 ID 참조를 저장한다. 각 역할은 이름·컴포넌트·독립적인 모델 선택을 소유한다. 메인은 같은 역할 편집기를 사용한다. 시스템과 연결은 워크플로우 소유를 유지하며 컴포넌트 인스턴스 ID는 모든 역할에 걸쳐 유일하다. 역할을 삭제해도 관련 연결을 자동 삭제하지 않고 기존 참조 누락 진단을 유지한다. 메인 참조가 사라지면 임의 역할로 대체하지 않고 진단한다.

legacy와 v2는 조회 시 하나의 역할과 메인 참조로 정규화한다. 역할 ID는 draft ID에서 결정적으로 생성하고 기존 컴포넌트 ID·연결·이름·미해석 설정·revision을 보존한다. 조회만으로 저장을 다시 쓰지 않는다. 다음 명시적 저장에서 v3를 기록한다. 저장 domain 버전을 올려 기존 문서를 열 수 없게 만들지 않는다. 새 형식의 downgrade는 지원하지 않으며 영속 타입 검토와 업그레이드 안내에 반영한다.

### 최초 모델과 기본값

사용자가 승인한 정책은 명시적 최초 선택·독립 복사다. 기존 초안에는 모델을 임의로 채우지 않는다. 워크플로우 최초 모델 선택을 기존 역할들의 초기값과 이후 추가 역할의 초기값으로 복사한다. 초기 선택은 문서에 보존한다. 이후 역할별 모델·추론 변경은 다른 역할이나 초기값으로 전파하지 않는다. 최초 선택을 반복하는 전체 역할 덮어쓰기 동작은 제공하지 않는다.

추론 미지정은 해당 역할에 명시된 모델의 제공자 기본 동작이며 부모 또는 메인 역할의 추론 설정 상속이 아니다. UI는 이 의미와 메타데이터에 공개된 기본 추론값을 구분해 표시한다. 모델 변경 때문에 기존 추론값이 미지원이 되면 그 값을 보존하고 진단한다. 자동으로 옵션을 바꾸거나 지우지 않는다.

### 카탈로그와 검증

Studio Host adapter가 공개 LLM API를 소비한다. 카탈로그에 없는 모델, 해제된 제공자, 지원하지 않는 추론값과 모델 미선택을 역할 ID·필드에 연결된 구조화 진단으로 반환한다. 네트워크·메타데이터 조회 실패는 미지원 판정이나 빈 목록으로 축약하지 않고 가용성 확인 실패로 표시한다. 진단이 있어도 형식이 유효한 초안 저장은 가능하다.

모델 서비스가 없는 프로필에서도 기존 초안 저장·조회는 유지한다. 선택과 지원 검증은 서비스 부재를 표시하고 실행 가능 성공을 반환하지 않는다. 선택 시 사용하는 카탈로그와 Host 검증은 같은 adapter를 소비한다. 검증 시 현재 등재 여부와 `resolveCallConfig`를 확인하되 반환된 기본값으로 초안을 수정하지 않는다. 구성 검증 성공은 라이브 인증·요청 성공 또는 실행 권한 보장이 아니다.

제공자 변경 이벤트와 재연결 시 카탈로그를 다시 읽고 현재 문서를 재검증한다. 느린 이전 조회나 검증 결과가 최신 편집·카탈로그 상태를 덮어쓰지 못하게 한다. 등록 해제는 선택값과 미저장 내용을 보존하며 새 선택만 제한한다. 기존 등록의 효과 수명과 해제 규칙을 유지한다.

## 검증 구분과 제한

S1–S3는 변경한 단일 테스트 파일을 반복 실행한다. 실제 Loader 테스트는 DSH 조합을 사용하고 외부 모델 응답만 fixture로 대체한다. 기존 역할 설정·등록 해제·저장 충돌 회귀를 유지한다. 실행·모델 요청을 추가하지 않는 이슈이므로 실행 프리셋이나 모델 요청을 임의로 만들지 않으며, 변경된 사용자 출력과 카탈로그 동작을 keyless 스냅샷·브라우저 테스트로 확인한다.

라이브 모델 호출과 설치 앱 배포는 keyless replay의 증거로 대체하지 않는다. 현재 GUI는 설치 checkout에서 제공되므로 이 작업 트리의 빌드가 자동 반영된다고 가정하지 않는다. 검증용 Web 배포가 기존 프로필 변경이나 별도 서버 실행을 요구하면 별도 승인을 받고, 승인 전에는 격리 browser scaffold 검증과 설치 GUI 미검증을 구분해 보고한다. 푸시·브랜치 통합·트래커 변경은 이번 구현 커밋에 포함하지 않는다.

## 진행 기록

S1–S3 구현을 완료했다. v3 저장·마이그레이션, 모델 adapter, 다중 역할 검증 focused 테스트 23개와 실제 Loader/Gateway 테스트 2개가 통과했다. UI 테스트 14개와 HTML 출력 스냅샷, Studio 전체 타입 검사·빌드가 통과했다. 격리된 Chrome scaffold에서 workflow browser 수용 테스트 1개가 통과했으며 라이트·다크·좁은 폭과 최초 모델·임의 역할 편집을 확인했다. 설치 GUI 배포나 라이브 모델 요청은 수행하지 않았다.

Standards/Spec 병렬 리뷰에서 지적한 stale 카탈로그 편집 차단과 서비스 부재·조회 실패 안내를 수정했다. 업그레이드 안내와 번역 쌍 검사, 링크 검사가 통과했다. `doc-sync`는 42개 통과 후 명세의 커밋 식별자 표기 1건을 거절했으며, 표기 수정 후 해당 gate가 통과했다. persistence catalog와 type history 검사도 통과했다.

요청된 저장소 전체 `pnpm run test`는 1회 실행하여 41,533개 통과, 31개 실패, expected fail 1개, skip 241개였다. 실패는 변경하지 않은 experimental worktree·tool-worktree, Inspector, SSH 테스트에 있다. 다수의 worktree 실패는 Apple Git 2.39.5의 `--no-lazy-fetch` 미지원이며 Inspector는 5초 timeout, SSH는 소켓 경로 거절 기대 불일치다. 전체 성공으로 해석하지 않는다. Studio 전체 테스트는 96개 중 95개 통과, preset-persistence의 플러그인 import 실패 1건을 확인했으며 workflow 테스트는 모두 통과했다.
