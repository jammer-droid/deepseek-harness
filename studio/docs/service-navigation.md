# Studio 서비스 탐색 구조

## 목적과 범위

Studio는 독립된 기능 영역을 제공하는 공통 셸이다. Preset Builder는 기본으로 선택되는 최상단 서비스이며 DSH 설정, 기존 고정 역할 설정, 디자인 미리보기, 실험 기능과 구분한다. 여기서 기능 영역 등록은 화면 진입점을 추가하는 기능이며 Workflow 내부의 시스템 등록과 다르다. 사용자가 구조와 UI 변경을 승인했으며 [이슈 15](issues/15-workflow-draft.md)의 완료 범위에 포함했다. 작업 브랜치는 `studio/service-navigation`이며 `studio-general`에서 분기했다.

## 소유권과 동작

셸은 서비스 선택과 표시, 공통 스타일을 담당한다. 각 기능은 자신의 표시 이름과 화면을 등록하고 플러그인 수명이 끝나면 등록을 해제한다. 서비스 추가 시 셸의 기능별 분기를 늘리지 않는다. 기존 Cordis 등록·Slot 구조를 우선 사용하며 별도의 실행 시스템이나 영속 저장 도메인은 추가하지 않는다.

서비스 이동은 편집 폐기가 아니다. 서비스 화면은 선택 전환에서 입력을 유지한다. 페이지 새로고침·플러그인 해제 후 미저장 내용 보존은 보장하지 않는다. 선택된 서비스가 해제되면 남은 서비스로 이동하며 사용할 수 없는 화면을 계속 표시하지 않는다.

실제 Workflow 초안은 목업과 분리한다. 디자인 미리보기는 기존 네 목업과 내부 탐색을 소유한다. DSH 설정 덮어쓰기와 고정 역할 Apply는 기존 의미를 유지한다. 서비스 탭은 좁은 화면에서도 접근 가능해야 하고 기존 디자인 시스템의 토큰·공용 부품을 사용한다. UI 문구는 한국어·영어·중국어를 제공한다.

## 단계

| ID | 결과 | 검증 |
| --- | --- | --- |
| S1 | 등록 및 탐색 구조, Preset Builder 기본 선택 | 동적 추가·해제·기본 순서·선택 상태 단위 테스트 |
| S2 | 기존 다섯 기능 영역 분리 | 기존 편집·저장 회귀, 전환 후 입력 보존 |
| S3 | 실제 구성과 반응형 화면 확인 | Studio build, Loader·브라우저 수용, 라이트·다크·좁은 폭 |
| S4 | 공용 문서와 최종 검증 기록 | 디자인 시스템·개발 안내 갱신, 문서 검사 |

S1·S2 구현과 S3 격리 브라우저 검증을 완료했다. 서비스 등록은 `local.dsh-studio.services` 목록 Slot의 `id`, `order`, locale 기반 `label`을 사용한다. Preset Builder·DSH 설정·역할 설정은 각 Client 플러그인이 등록하고, 셸은 디자인 미리보기와 실험 화면을 등록한다. 실험 하위 기능은 기존 `local.dsh-studio.features` Slot을 사용한다.

검증: Studio 빌드, 테스트 타입 검사, Node 테스트 63개, Workflow·역할 편집·전체 실행 브라우저 테스트가 통과했다. Workflow 테스트는 서비스 전환 중 미저장 지시문을 보존하고 두 초안을 저장·재조회한다. 브라우저에서 다섯 서비스의 등록 순서와 Preset Builder 기본 선택을 확인하며, 라이트·다크 테마의 720px 뷰포트에서 모든 메뉴를 선택하고 하나의 서비스 화면만 표시되는지 확인한다. 역할 테스트는 라이트·다크 테마와 720px 뷰포트에서 넘침과 키보드 포커스를 확인한다.

Preset Builder의 Workflow 좌측 메뉴는 기존 초안 편집 화면을 연다. [공용 상세 레이아웃](../src/detail-layout.tsx)을 디자인 미리보기와 공유하여 좌측 메뉴와 우측 스크롤 본문을 일치시킨다. 이 변경 후 빌드, 관련 단위 테스트 6개와 격리 Chrome Workflow 테스트가 통과했다.

에이전트는 설치 프로필 배포를 수행하지 않았다. 사용자는 Web에서 변경을 확인하고 이슈 15 종료를 승인했다. 실제 프리셋 적용·활성화·실행은 범위 밖이다.
