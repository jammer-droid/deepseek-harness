> **이력 자료:** `feat/lean-agent`는 기존 기능 구현을 제거한 셸 전용 브랜치입니다. 이 문서의 workflow 기능·검증 기록은 분기 전 기준이며 현재 배포 기능이 아닙니다.

# 에이전트 최적화 실험

## 요약

사용자 요청에 따라 Experiments에서 출력 축소, Goal/Todo 제한, 최적화 프롬프트 조립, 읽기 묶기, 작업 의존성 및 대기 정책을 선택한다. 각 기능은 끄기·메인·서브·둘 다 중 하나를 사용한다. 구현 기준은 설치된 `@local/dsh-test-plugin`이며 원문 보존, 순차 batch, 성공 의존성 및 소유 작업만 취소하는 동작을 유지한다.

## 적용 결정

- 프로필 설정은 사용자 전용 Remote에서 명시적으로 저장·적용한다. 모델 도구로 설정을 수정하지 않는다.
- 초기 설정은 모두 꺼짐이다. 기존 값인 출력 8192자, 미리보기 총 1024자, batch 최대 8개·read 최대 200줄, 작업 대기 120000ms·Bash foreground 요청 600000ms를 사용하며 사용자 편집 가능한 수치는 검증한다.
- 각 에이전트 시작 시 설정을 고정한다. 실행 중 에이전트의 도구·프롬프트·작업을 UI 변경으로 바꾸거나 취소하지 않는다. 부모와 이후 생성되는 자식은 서로 다른 설정 리비전을 가질 수 있다.
- Goal 제한은 도구 제시뿐 아니라 직접 실행을 차단하고 해당 에이전트의 자동 진행 권한을 해제한다. 저장된 목표의 내용·단계·리비전은 유지한다. 공통 Goal 드라이버 자체를 전체 프로필에서 제거하지 않는다.
- 최적화 프롬프트 조립은 관련 없는 섹션·컨텍스트·변수를 유지한다. native 전용 정책을 선택한 에이전트만 native 도구 제공 방식을 사용한다.
- 취소·종료 정리는 기능을 켜고 끄는 것과 무관한 안전 보장이다. 실험이 소유한 작업만 취소하고 종료를 기다린다. 일반 Bash 작업을 임의로 소유하거나 종료하지 않는다.
- 설치된 실험 패키지는 수정하지 않는다. Studio 소스에 필요한 로직을 편입하며 런타임 차이로 변경하는 부분과 검증 한계를 기록한다.

## 구현 단계

| 단계 | 결과 | 선행 | 수용 조건 |
| --- | --- | --- | --- |
| S1 | 적용 범위·확장 지점 확인 | 없음 | 메인/서브 구분, Goal 차단, 정책 수명과 API 확인 |
| S2 | 설정 저장 및 실행 정책 | S1 | 리비전 충돌·저장 실패 보존, 대상별 도구·프롬프트·출력·의존성 격리 |
| S3 | Experiments 편집 UI | S2 | ko/en/zh, 적용 대상·수치 검증·저장 결과·신규 에이전트 안내 |
| S4 | 검증과 문서 | S2, S3 | 단위·실제 Loader·사용자 및 모델 출력·브라우저 검증 |

## 검증 기록

설정 저장·UI·정책 구현과 Host/Client 타입 검사, 설정 저장 테스트 3개, Chrome 브라우저의 저장·재접속·라이트/다크·480px 폭 검증을 수행했다. Desktop 0.2.0-rc.2 대상 선언으로 생성·타입 검사·패키징도 통과했다. 기본 Playwright Chromium은 설치되지 않아 브라우저 검증은 설치된 Chrome 채널을 사용했다. 실사용 프로필 설치 결과는 배포 응답의 application 값으로 확인하며, 실행 중 앱을 강제로 재시작하지 않는다.

정책 테스트는 Studio 디렉터리에서 실행한다. `npm --prefix studio run test:experiments`는 소스를 빌드한 뒤 설정·정책 테스트를 실행한다. 루트의 다른 tsconfig를 암묵적으로 사용하는 직접 `tsx` 호출은 source/built Cordis scope를 혼합할 수 있다. Loader의 도구 노출·직접 실행 차단·해제, 실제 AgentLoop/GoalRoundDriver의 메인 자동 진행 차단과 서브 자동 진행 유지, 작업 성공 의존성·취소 대기, 프롬프트 불변성 및 출력 축소를 포함해 총 13개 테스트가 통과했다. 작업 의존성 테스트의 Job API는 제어 가능한 테스트 구현이며 실제 shell subprocess 전체 종료는 별도 검증 범위다.

## 제한과 운영

- 기존 `dsh-test-plugin`이 같은 에이전트에 제공하는 `test_batch_read` 도구가 있으면 실험 활성화를 거부한다. 중복 출력 축소와 도구 재등록을 피하려면 해당 프리셋의 기존 플러그인을 비활성화한 뒤 새 에이전트를 시작한다. Studio는 다른 플러그인을 자동으로 비활성화하지 않는다.
- Bash foreground 값은 기존 Bash 도구에 전달하는 요청값이다. 실제 대기는 기존 런타임의 상한을 초과하지 않는다. 작업 결과 대기는 설정된 기본값·상한으로 제한한다.
- Bash가 background job으로 승격되면 공개 Job API만으로 종료 코드를 판정할 수 없으므로 의존 작업의 성공으로 간주하지 않는다. 성공 여부가 불명확한 선행 작업에 의존한 작업은 실행하지 않는다.
- 전체 시스템 프롬프트 override는 assemble waterfall 뒤 원본 섹션을 복원한다. 최적화 지침은 시스템 문자열 대신 조립된 런타임 컨텍스트에 추가하며, AgentLoop가 이를 세션 로그와 모델 입력에 반영한다. override 원문·다른 컨텍스트·변수는 유지한다. Desktop 0.2.0-rc.2에서 runtime context를 비활성화하면 모든 context가 제거되므로 최적화 지침도 주입되지 않는다. 공개 API로 이 억제를 우회하지 않는다. Goal 도구 실행 차단과 자동 진행 권한 해제는 프롬프트 텍스트와 별개로 적용한다.

## UI와 호환성

일괄 읽기 도구 이름은 `read_batch`다. 이전 Studio의 `test_batch_read`를 지정한 프롬프트나 자동 호출은 `read_batch`로 수정하고 새 에이전트에서 확인한다. 이전 이름의 별칭은 제공하지 않는다. 기존 test-plugin 충돌 검사는 해당 플러그인이 제공하는 `test_batch_read` 이름을 그대로 검사한다.

ko/en/zh 모두 최적화 프롬프트 조립으로 표시하며 저장 키 `headless`와 끄기·메인·서브·둘 다 값은 유지한다. 데이터 삭제나 파괴적 마이그레이션은 없다. Experiments는 Preset Builder와 같은 DetailLayout 내비게이션·독립 스크롤 콘텐츠를 사용한다. 테스트 타이머와 데모 Client 패키지·번들 기여는 제거하고 실제 Studio 서비스와 Experiments는 유지한다.
