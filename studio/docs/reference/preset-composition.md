# Studio 프롬프트 구성 편집

> **초기 설계가 포함된 참고 문서:** 아래 minimal 기반 흐름·탭 명칭·역할 저장 전용 설명은 초기 단계 기록이다. 이후 [Master](master-preset.md), [Config 편집 기록](../verification/config-editor-progress.md), [역할 실행](role-preview.md), [Optimized 도구](optimized-tools.md)가 추가되었다. 현재 기능의 출발점은 [Studio 개요](../../README.md)다.

## 편집 순서

1. 프롬프트 영역에서 Persona 기본 지침(prefix)과 후행 지침(suffix)을 편집한다. minimal 원본을 불러오며 각 필드는 원본 사용으로 복귀할 수 있다.
2. Studio 전용 지침을 편집한다. 플러그인 선택기와 컨텍스트·압축·도구 표시 방식 설정은 이 화면에서 제공하지 않는다. Persona는 항상 포함한다.
3. 도구는 기본 선택 없이 시작한다. 상세에서 설명, 중첩 객체 인자 설명, 연결된 시스템 지침을 편집한다. 타입·필수 여부·실행 함수·권한은 변경하지 않는다.
4. 추가 지침을 입력하고 실제 DSH 조립 미리보기를 실행한다. 모델 문자열은 testLLM 고정이며 모델 호출은 없다.
5. 페이지 최상단 우측의 미리보기 버튼으로 결과 모달을 연다. 조립 중 상태와 오류도 모달 안에 표시한다. 왼쪽은 섹션명, 오른쪽은 조립된 내용이며 도구 스키마가 아래로 이어진다. 닫기/Escape로 닫는다.

도구 카드의 연필 아이콘은 선택 여부와 독립적으로 모달 편집기를 연다. 도구 설명(전체 설명), 인자 설명(스키마의 설명 문구만), 도구 사용 지침(시스템 프롬프트 본문)을 각각 제목과 반영 위치 안내로 구분한다. 변경은 초안에 즉시 반영되며 닫기/Escape로 모달을 닫는다. 같은 시스템 섹션을 참조하는 도구는 지침을 공유한다.

선택 해제한 항목의 override는 요청에서 제외한다. 원본 사용은 override 삭제이며 빈 문자열과 다르다. 저장 전 편집 상태는 메모리에 보관한다. 프리셋 생성의 저장 버튼은 프롬프트·도구와 작업 편의·서브에이전트 초안을 함께 프로필별 Studio 저장소에 기록한다.

## 프리셋 관리

Studio 메뉴는 프리셋 목록 / 프리셋 생성 두 가지다. 생성 내부 탭 순서는 프롬프트·도구 → 작업 편의 → 서브에이전트 설정이며 탭 이동 시 입력을 유지한다. 저장 후 목록으로 돌아가며 생성 양식은 새 프리셋을 위해 초기화한다.

목록은 공유 Studio 카드와 DSH 테마 토큰으로 표시한다. DSH에 반영하면 공개 agentPresets 등록 API로 Studio 소유 ID의 프리셋을 등록한다. Persona·Studio 지침·선택 도구·설명 override는 실제 구성에 포함한다. 작업 편의·서브에이전트 설정은 저장만 지원하며 실행 미연결 안내를 표시한다. 등록은 재시작 후 마지막 반영 시점의 구성으로 복원한다. 삭제 확인 후 저장된 항목과 Studio 소유 등록만 제거하며 기존 대화는 삭제하지 않는다.

미리보기는 도구 override와 함께 임시 Studio scope에서 실제 조립한다. 미리보기 또는 저장만으로 실행 중인 대화를 변경하지 않는다. DSH에 반영된 프리셋은 새 에이전트에서 선택할 수 있다.

## 기여 플러그인 참고 (편집 대상 목록이 아님)

| 플러그인 | 기여 위치 |
| --- | --- |
| persona | 시스템 본문 및 런타임 컨텍스트 포함 정책 |
| agent-instructions | 실행 직전 작업 지침 메시지 |
| time-context | 실행 직전 시간 메시지 |
| skill-filesystem | 스킬 탐색 및 간접 카탈로그 메시지 |
| compaction-basic | 실행 중 메시지 기록 압축 |
| compaction-tool-result-pruner | 압축용 도구 결과 축약 |
| agent-tool-presentation | native/PTC 도구 표현 및 생성 지침 |

실행 직전 메시지·압축은 정적 assemble 미리보기에서 실행하지 않는다. 전역 환경 기여는 위 목록과 별개이며 원본 런타임 정책에 따른다. plan-mode는 exit_plan_mode를 소유하므로 비도구 플러그인으로 분류하지 않는다. command-goal/command-compact, terminal, workflow-ptc는 직접 프롬프트 기여자가 아니다.

## 지원 경계

- Persona complete는 다른 기여를 숨기지 않도록 false 고정이다. minimal의 includeRuntimeContext 원본 false는 유지하며 두 설정은 UI에 노출하지 않는다.
- 작업 지침·시간·스킬·압축·도구 표시 플러그인의 카탈로그 분류는 유지하지만 현재 편집 UI에서 선택하거나 변경하지 않는다.
- 인자 스키마 편집은 설명에 한정한다. 배열 내부 및 조합 스키마 구조 변경은 미지원이다.
- 도구별 본문 지침은 확인된 공개 섹션에 한정한다. 모든 동적 플러그인 지침을 임의의 문자열로 교체하지 않는다.
- 미리보기 cwd는 서버 작업 디렉터리다. 실제 세션의 작업 지침·시간·스킬·압축 실행 결과와 동일하다고 주장하지 않는다.
- 도구는 실행 서버 카탈로그 기준이며 다른 Desktop 서버와 자동 공유하지 않는다. 호환되지 않는 여러 프리셋의 실행 클로저를 혼합하지 않는다.
- 수정하지 않은 DSH에 Studio만 패키징하여 검증한다. 시각 확인은 사용자 담당이다.

상세 이력은 [이슈 24](../issues/24-preset-composition.md)를 참고한다.
