# Studio 마스터 프리셋

## 구성과 수명

Studio가 Loader 초기화 완료 후 설치된 `standard` 선언을 읽어 `studio-master`를 등록한다. 무조건 모든 설치 플러그인을 합치지 않고, 의존성 그룹이 유지된 기준 구성을 사용한다. 마스터 등록만으로 플러그인이 활성화되며 실제 에이전트를 생성할 필요는 없다.

도구·프롬프트 카탈로그는 마스터 scope에서 조회한다. 사용자 프리셋이나 기존 프리셋 전체를 순회하지 않는다. Studio 목록에는 읽기 전용 마스터를 포함하고 적용·삭제 버튼을 비활성화한다. 서버의 사용자 프리셋 소유권 검사가 마스터 저장·적용·삭제를 거부한다. DSH 자체의 일반 프리셋 목록에서는 보일 수 있다.

## 파생 프리셋

새 작성 요청의 원본은 `studio-master`다. 마스터의 제공자 선언과 의존성 구성을 읽고, 기존 편집기가 지원하는 제공자 Config·도구 설명·프롬프트 재정의를 합성한다. 선택 도구는 정책으로 제한하며, 도구의 실행 콜백을 복사하지 않는다. 제공자 단위 가지치기는 하지 않으므로 선택하지 않은 도구 제공자도 활성화될 수 있다.

저장 요청은 원본 ID와 재정의를 보관한다. 적용할 때 독립 구성을 만들고 마지막 적용 구성을 저장한다. 이후 마스터 변경이 기존 적용 프리셋에 자동 전파되지 않는다. 기존 minimal 기반 저장 데이터는 호환 동작을 유지한다.

## 검증

수정하지 않은 DSH 0.2.0-rc.2의 격리 프로필(19388)에 패키징한 Studio를 설치했다.

- 실제 마스터 도구 25개 조회.
- 마스터 수정·삭제·적용 RPC 거부 확인.
- read 하나만 선택한 파생 미리보기에서 도구 목록 제한, 설명 재정의, 프롬프트 재정의 확인.
- 파생 프리셋 저장·실제 등록·삭제 확인.
- 카탈로그 스냅샷 불변 확인.
- Studio 테스트 34개 및 타입 검사·빌드 통과. 기존 UI fixture가 minimal을 전제로 해 처음 한 건 실패했으며 마스터 기준으로 변경 후 통과.

## 남은 범위

일반적인 모든 플러그인 Config를 편집하는 UI와 Spill Config 재정의는 이번 연결에 포함되지 않았다. 기존 실행 설정 카드와 어댑터가 남아 있다. 카탈로그가 채워졌다는 것을 임의 Config 편집까지 지원한다는 의미로 해석하면 안 된다. 마스터 자동 확장 및 외부 플러그인 추가 UI도 별도 작업이다.
