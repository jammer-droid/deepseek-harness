# Studio 프리셋 수명과 의존성 책임

## 범위

Studio가 저장·적용한 Master, Optimized 및 사용자 프리셋의 실행 수명과 책임을 정의한다. Studio는 편집기와 실행 프리셋의 등록 주체이며, 독립 실행용 사본을 사용자 프로필에 별도로 발행하지 않는다. 별도 외부 번들로 설치한 프리셋의 소유권은 해당 번들에 있다.

## 수명 정책

Studio 프리셋을 사용하는 세션의 실행·재개에는 Studio 활성화, 해당 프리셋 등록 및 유효한 실행 의존성이 필요하다. Studio 비활성화·제거 시 소유 프리셋 등록을 해제한다. 프리셋 삭제·적용 해제도 해당 등록을 없애므로 이후 세션 재개가 불가능할 수 있다. 다른 프리셋으로 자동 대체하거나 도구 제한을 제거하여 실행하지 않는다.

프리셋 등록 해제는 대화 기록 삭제가 아니다. 기록의 보존·조회와 Agent 실행·재개를 구분한다. 이미 살아 있는 Agent는 DSH가 유지한 revision으로 동작할 수 있지만 Studio 종료 후 지속 실행은 보장하지 않는다. 이 정책은 활성 Agent의 즉시 중단 또는 권한 회수를 약속하지 않는다.

Studio 종료는 프로필의 저장 초안과 마지막 적용본을 삭제하지 않는다. 재활성화 시 마지막 적용본의 동일 ID를 등록하며, 필요한 의존성이 유효하면 해당 세션을 재개할 수 있다. 적용 해제·삭제한 프리셋을 재활성화만으로 자동 복원하지 않는다. 재설치 또한 저장 데이터와 호환 가능한 의존성이 남아 있어야 복구할 수 있다.

같은 ID의 프리셋 재적용과 세션 생성 당시 revision의 영구 보존은 별개다. 이 정책은 프로세스 재시작 후 모든 과거 revision을 재현한다는 보장이 아니다.

## Studio의 책임

- 적용 시 명시된 구성의 활성화, 필수 도구와 지원하는 정책·Config 조합을 검증한다. 검증 실패를 적용 성공으로 보고하지 않는다.
- 마지막 적용본을 초안과 분리하여 저장한다. 적용·복원 실패 때문에 저장된 구성을 임의로 삭제하거나 다른 구성으로 교체하지 않는다.
- 활성화 시 저장된 적용본을 복원하고 실패 원인을 제공한다. 의존성 누락을 정상 상태로 위장하지 않는다.
- 도구 선택은 이름만 같은 다른 프리셋 구현으로 자동 대체하지 않는다. 선택한 기준 구성과 명시적 제공자가 출처를 결정한다.
- Studio allowlist는 도구 노출과 실제 실행에 일관되게 적용한다. 공개 API로 보장할 수 없는 조합은 제한과 진단을 명시하며, 실행 차단을 완화하지 않는다.
- 기존 사용자 프리셋·전역 설정을 직접 수정하지 않으며, Studio 소유 등록과 프로필별 저장 데이터만 관리한다.

외부 플러그인의 설치·업데이트·제거는 사용자의 명시적 패키지 관리 작업이다. Studio가 의존성을 임의로 설치·삭제하거나 버전을 강제 변경하지 않는다. 적용 시 검증은 외부 플러그인의 향후 동적 등록이나 업데이트까지 보증하지 않으므로, 실행 시 정책 검사도 유지한다.

## 경계

도구 allowlist는 플러그인 샌드박스가 아니다. 제공자의 활성화 코드, 이벤트·서비스 등록과 외부 부수효과는 도구 선택만으로 차단되지 않는다. 추가 제공자 검증도 실제 코드를 활성화하므로 신뢰하는 패키지만 사용한다.

Studio 정책은 DSH의 승인·파일 접근·다른 guard를 완화하지 않는다. 종속 모듈이 없을 때 policy·roles 등을 생략하여 대화를 재개하지 않는다. 의존 모듈의 정확한 버전 고정, 임의 외부 코드의 부수효과 롤백과 실시간 의존성 감시는 이 정책의 보장 범위가 아니다.

## 검증 기준

수정하지 않은 지원 DSH의 격리 프로필에서 비활성화 → 재개 실패 → 재활성화 → 정상 재개를 확인한다. 적용 해제·삭제, 의존성 누락, 복원 실패 시 저장본 보존, 기존 사용자 환경 불변도 구분하여 검사한다. workspace 단위 테스트는 독립 배포 검증을 대신하지 않는다. 구현별 증거와 남은 제한은 검증 기록에 별도로 남긴다.
