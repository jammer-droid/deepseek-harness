# Studio 서비스 탐색 구조

Studio 셸은 사이드바 진입점, 서비스 선택, 표시와 공통 스타일만 담당한다. 분기 초기에는 기본 등록 기능 없이 빈 상태만 표시했지만, 이후 프리셋 편집 기능이 등록되었다. 빈 상태는 등록 서비스가 없을 때의 동작이다.

## 등록과 수명

새 기능은 `local.dsh-studio.services` 목록 Slot에 `id`, `order`, locale 기반 `label`로 등록한다. 셸은 등록 목록을 순서대로 표시하고 첫 항목을 기본 선택한다. 등록·해제와 locale 변경을 구독하며 기능별 분기를 소유하지 않는다.

[ServiceLayout](../../src/service-layout.tsx)은 선택하지 않은 서비스도 마운트를 유지한다. `active` owner prop으로 현재 선택 여부를 전달한다. 선택한 서비스가 제거되면 남은 첫 서비스로 돌아가며, 모두 제거되면 ko·en·zh 빈 상태 문구를 표시한다. 새로고침·플러그인 해제 후 미저장 값 보존은 보장하지 않는다.

[DetailLayout](../../src/detail-layout.tsx)은 이전 디자인 미리보기의 좌측 메뉴·스크롤 본문 골격을 유지한다. 기능 내 페이지 변경 시 본문만 맨 위로 이동하며 숨겨진 페이지는 마운트를 유지한다. 새로운 서비스는 필요에 따라 이 레이아웃과 [디자인 시스템](../development/design-system.md)의 부품을 사용한다.

## 검증 경계

서비스 전환 중 입력 유지·등록 해제·빈 상태는 [단위 테스트](../../test/service-layout.test.mjs)로 확인한다. 셸의 패널·사이드바 및 현재 번들 등록 계약은 [번들 테스트](../../test/lean-shell.test.mjs)로 확인한다. 실제 설치 화면의 테마·반응형·포커스 검증은 별도로 필요하다.
