# 역할 기반 서브에이전트 프리뷰

## 화면에서 확인할 흐름

1. Studio → 프리셋 생성 → 서브에이전트 설정을 연다.
2. 이름, 역할 설명, 모델, 추론 수준, 스폰 방식, 사용자 지침을 입력한다.
3. 역할 카드를 선택해 편집한다. 모델은 `sessionController.modelCatalog()`가 제공하는 목록에서 선택한다. 특정 모델의 추론 수준도 해당 모델의 지원 목록에서 선택한다. 부모 모델 상속 시 추론도 상속하며 모델을 바꾸면 추론 선택을 기본값으로 초기화한다. 조회 실패·일부 공급자 실패·사용 불가한 저장 모델은 표시한다.
4. 프리셋을 저장하고 목록에서 **DSH에 반영**한다.
5. 새 대화를 만들면서 해당 프리셋을 선택한다. 기존 대화에는 새 프리셋 구성이 소급 적용되지 않는다.
6. 역할 목록 조회 후 Researcher 또는 Reviewer 역할에 작업을 맡기도록 요청한다.

Fresh 작업은 독립적인 설명이 필요하다. Fork는 부모의 완료된 대화를 물려받는다. 역할별 Spill, 실행 대기시간, 임의 Config 재정의는 이번 범위에 포함하지 않는다.

## 편집·재반영·반영 해제

`agentPresets.register()`의 공개 disposer로 DSH 등록만 해제할 수 있다. 목록의 **편집**으로 저장 구성을 불러오고 저장하면 `modified`가 된다. **DSH에 다시 반영**하면 저장된 최신 구성으로 등록한다. **DSH 반영 해제**는 저장본을 유지하되 applied 스냅샷을 제거하여 재시작 후에도 등록되지 않게 한다. 저장 실패 시 이전 등록을 복구한다. 기존 대화는 기존 revision을 유지하며 변경은 새 대화에서 확인한다.

사용자 지침은 네이티브 subagent의 `persona`이다. 비어 있으면 persona 인자를 생략하여 배포 기본값을 유지한다. 모델 선택 UI는 사용자에 의한 역할 설정이며 기존 자율 모델 선택 허용 목록을 편집하거나 복제하지 않는다.

## 자동 검증 결과

- Studio 타입 검사·빌드 및 전체 50개 테스트 통과. 역할 카드 편집, 모델별 추론 옵션과 모델 변경 시 초기화, 반영 해제 후 재시작·재반영을 포함한다.
- rc.2 설치 프리뷰에서 역할 저장·수정·재반영·해제·복구 검사 통과. 모델 API에서 공급자 1개·모델 2개 반환 확인. 시각 검증은 미실행.
- 미수정 DSH 0.2.0-rc.2에 패키징한 Studio 설치 후 역할 저장·재조회·프리셋 활성화 검사 통과.
- master 프리셋 읽기 전용 보호, 28개 도구 구성, Config/설명 덮어쓰기, 적용·정리 검사 통과.
- 실제 LLM 자식 생성·완료 알림은 아직 실행하지 않았다. 두 공개 호출 API 경로는 테스트 대역으로 확인했다.

## 검증 경계

프리뷰는 수정하지 않은 DSH 0.2.0-rc.2와 별도 lean-agent-web 프로필/19388 포트를 사용한다. 19387 사용자 앱은 변경하지 않는다. 자동 검증의 프리셋 등록 성공과 실제 유료 모델 호출 성공은 별개다. 실제 모델 호출과 라이트·다크·좁은 화면의 시각 확인은 별도 확인이 필요하다.
