# Studio 워크플로우 업그레이드

## 적용 범위

이 안내는 Studio 워크플로우 초안 저장 형식과 생성된 Remote API 호출자를 대상으로 한다. 기존 General 설정이나 고정 역할 설정, DSH Session 형식은 변경하지 않는다. Studio는 기존 공개 API를 사용하는 독립 플러그인이며 카탈로그 갱신을 위해 DSH 본체 수정이나 코어 재빌드를 요구하지 않는다.

## 저장 형식과 읽기

현재 초안은 `documentVersion: 3`, `roles` 배열, `mainRoleId`, 역할별 모델·컴포넌트, 워크플로우 시스템과 포트 연결을 보관한다. v2의 인라인 `mainRole`은 역할 참조로 정규화한다. legacy 초안의 컴포넌트에는 초안 ID와 원래 위치에서 결정적인 인스턴스 ID를 부여하며, 기존 메인 역할에도 결정적인 역할 ID를 부여한다. 기존 인스턴스 ID·연결·설정은 보존하고 모델은 자동으로 지정하지 않는다.

읽기는 메모리에서만 정규화하며 저장 domain 버전 1, 기존 revision과 저장소 내용은 바꾸지 않는다. 다음 명시적 저장에서 기존 revision을 비교한 뒤 v3 문서를 기록한다. 구조적으로 유효한 초안은 누락된 시스템, 잘못된 설정 값이나 모델 선택이 있어도 저장할 수 있다. 저장 성공은 구성 검증 통과·프리셋 적용·실행 가능을 뜻하지 않는다.

## 인스턴스 사용 여부

컴포넌트와 시스템 인스턴스의 `enabled?: boolean`은 v3의 선택적 필드이며 없으면 활성이다. legacy·v2·기존 v3 문서는 이 기본값을 사용한다. 사용 안 함은 전역 플러그인 해제나 삭제가 아니며 해당 워크플로우의 인스턴스에만 적용한다. 설정과 연결은 저장하고 다시 열어도 유지한다.

비활성 인스턴스 자체의 구성·등록·의미 검증과 그 인스턴스에 닿는 연결 검증은 생략한다. 활성 항목의 필수 시스템과 최소 포트 연결 수는 활성 항목과 연결만으로 충족해야 한다. 문서 형식과 ID 중복 검사는 비활성 항목에도 적용한다. 재활성화하면 보존한 설정과 연결을 다시 정상 검증한다.

## 업그레이드 순서

1. 새 Studio를 사용하기 전에 설정된 워크플로우 초안 저장소를 백업한다. 새 형식으로 저장한 뒤에도 업그레이드 전 백업을 덮어쓰지 않는다.
2. 기존 초안을 열고 이름, 역할, 컴포넌트 순서, 시스템 설정과 연결이 유지되는지 확인한다. 등록이 없거나 버전이 맞지 않는 항목은 읽기 전용으로 남는다. 가용성을 복구하려고 삭제하지 말고 같은 버전의 등록을 복구한다. 자동 컴포넌트 버전 변환은 제공하지 않는다.
3. 초기 모델을 명시적으로 선택하고 각 역할의 선택을 확인한다. 최초 선택은 기존 역할들에 복사하고 새 역할의 초기값으로 사용한다. 이후 역할별 모델·추론 설정은 독립적으로 편집한다.
4. 명시적으로 저장하고 다시 열어 역할 이름, 모델 선택, 컴포넌트, 시스템, 연결과 사용 여부가 유지되는지 확인한다. 구성 진단은 별도로 해결한다. 모델·추론 지원 검증 통과도 인증, 실제 모델 요청 성공, 권한 또는 실행 지원을 보장하지 않는다.
5. 사용자 정의 Remote 호출자는 v3 문서를 보내고 Promise를 반환하는 `studioWorkflows.validate()`를 `await`하도록 수정한다. Studio Host와 생성된 클라이언트를 함께 갱신한다. 코어를 재빌드하는 절차가 아니다.

## 카탈로그 갱신

화면 진입·재진입·재연결·수동 새로고침에서 기존 Remote 조회로 가용성을 확인한다. 실시간 카탈로그 이벤트 구독이나 자동 polling은 없다. 갱신은 초안을 다시 읽지 않으므로 미저장 설정과 연결을 보존한다. 조회 실패는 표시하고 가용성이 확인되기 전까지 새 항목 추가를 막는다.

## 이전 버전으로 되돌리기

새로 저장한 v3 초안을 이전 Studio 코드로 읽는 downgrade는 지원하지 않는다. 같은 v3이라도 `enabled: false`를 해석하지 못하는 이전 빌드에 새 문서를 넘기지 않는다. 되돌려야 하면 업그레이드 전 저장소 백업을 복원한다. 자동 downgrade는 제공하지 않는다.

공개 서비스와 저장 실패 복구는 [워크플로우 패키지](../packages/workflows/README.md), 기능 범위는 [워크플로우 명세](workflow-specification.md)를 참고한다.
