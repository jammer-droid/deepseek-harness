# Pixie Gate 실동작 점검 지침

이 세션은 DSH Studio Pixie Gate가 실제로 동작하는지 확인하는 점검 세션이다. 아래 단계를 순서대로 수행하고, 각 단계에서 **실제로 받은 내용**만 보고한다. 추측하거나 기대값을 대신 쓰지 않는다.

이 세션에는 다음 게이트가 걸려 있다(설정은 Studio → Pixie → 게이트).

| 게이트 | 언제 | 하는 일 |
| --- | --- | --- |
| R5 지시 점검 | 사용자가 지시를 보낼 때 | 지시가 `[GATE]`로 시작할 때만 훅 스크립트가 `pixie ask/judge`로 요약·완료 조건 판정을 만들고, Pixie가 완료 조건이 없으면 막는다. 있으면 요약을 덧붙인다 |
| R5 파일 결과 | 도구 결과가 나왔을 때 | `read`로 `gate-sample.txt`를 읽은 결과에만 실행되어, 도구 결과와 함께 `[PIXIE CHECKED <줄 수> lines] …` 컨텍스트 메시지를 덧붙인다 |
| R5 답변 점검 | 에이전트 답변이 끝났을 때 | 답변 마지막 줄이 정확히 `GATE-OK`가 아니면 다시 하라고 지시한다(턴당 1회) |

## 단계

1. `gate-sample.txt`를 `read` 도구로 읽는다. 받은 도구 결과의 첫 줄과, 도구 결과와 함께 받은 컨텍스트 메시지가 있으면 그대로 인용한다.
2. `other.txt`를 `read` 도구로 읽는다. 받은 도구 결과의 첫 줄과, 함께 받은 컨텍스트 메시지가 있으면 그대로 인용한다.
3. 내 지시 바로 뒤에 따로 받은 메시지(예: `Pixie 요약:`으로 시작하는 Pixie Gate 메시지)와 단계 1의 컨텍스트 메시지를 모두 그대로 인용한다. 없으면 "없음"이라고 쓴다.
4. 단계 1과 2의 결과가 서로 다른 형태인지, 왜 그런지 이 지침의 표를 근거로 한 문장으로 설명한다.
5. 처음 답변은 마지막 줄에 완료 표시를 쓰지 **말고** 마친다. 다시 하라는 지시를 받으면, 받은 지시 문구를 그대로 인용하고 답변 마지막 줄에 `GATE-OK`를 쓴다.

파일을 수정하거나 다른 도구를 쓰지 않는다.
