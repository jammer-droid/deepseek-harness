# Jev 결정 엔진 실사용 확인 절차 (#27)

> fork 내부 확인용이다. 공개 안내는 [Pixie Gate 가이드](../../release/docs/appendix/pixie-gate.ko.md)를 따른다.

이 문서는 #27 결정 엔진을 desktop 앱에서 실제로 써 보는 세 가지 상황의 준비, 진행, 판정 기준을 정리한다. 1번은 사용자가 세션에서 스킬로 진행하고, 2·3번은 Pixie 게이트가 자동으로 실행된다. 각 상황의 결과는 [보고 양식](#보고-양식)으로 남긴다.

| # | 상황 | 무엇이 판정하나 | 무엇이 행동하나 |
|---|---|---|---|
| 1 | Pixie 로케일 한국어 교정 | 에이전트가 부르는 `judge` 도구(Jev) | 메인 에이전트가 고칠 안을 만들고 승인받아 수정 |
| 2 | 영어 최종 답변을 한국어로 | 답변 끝 게이트 스크립트의 `pixie judge`(Jev) | Pixie가 번역하고, 스크립트가 exit 11로 메모를 남김 |
| 3 | 서브에이전트 라우팅 | 도구 실행 전 게이트 스크립트의 `pixie judge`(Jev) | 스크립트가 통과(exit 10) 또는 거부(exit 11) |

## 공통 전제

확인 시점: 2026-10-16. 아래 값과 다르면 해당 상황을 시작하지 말고 다른 점을 적는다.

- DSH desktop `0.2.0-rc.2`. Studio는 로컬 빌드(`node studio/dev.mjs --desktop`)로 설치했고, `judge.js`·`skills/`를 포함한 빌드를 앱이 불러온 상태다. 앱 시작 시각이 Studio 설치 시각보다 늦어야 한다.
- 결정 엔진: **Studio → Pixie → 게이트 → 결정 엔진**이 `Jev`, 키 상태가 `설정됨 · 출처: file`. 키가 환경 변수에서 오면(`출처: env`) 실행 중인 앱 또는 터미널에 키가 남아 있는 것이다.
- Pixie 모델: `deepseek-account / deepseek-flash / low` (번역에 쓰인다).
- 테스트 프리셋: `Test Preset` (`studio-user-da0ba041-2c2c-4eef-8378-2160593ccfd1`). 도구에 `judge`, `read`, `edit`, `bash`가 있고, 역할은 Worker(codex/gpt-6-astra, medium), Reviewer(deepseek-flash, low), Researcher(deepseek-flash, high).
- `jq`가 `/usr/bin/jq`에 있다.
- 게이트 정의는 실행할 때마다 파일에서 읽는다. 게이트를 바꿔도 앱을 다시 시작할 필요가 없다. 스킬은 새 세션부터 보인다.
- Jev로 보내는 텍스트(로케일 문구, 최종 답변, 위임 작업 내용)는 TypeSafe로 전송된다.

## 1. Pixie 로케일 한국어 교정 (스킬 + `judge` 도구)

### 준비

- 스킬: `~/.dsh/skills/studio-ko-locale-review/SKILL.md`. 대상 파일 6개, 판정 질문 3종(자연스러움 score, 의미 일치 noul, 합쇼체 noul), 기준값(자연스러움 < 1.5, 의미 < 0.6, 말투 < 0.5이면 교정 대상), 승인 후 수정, 수정 뒤 검사가 들어 있다.
- 작업 디렉터리는 DSH 저장소 루트(`/Users/home/playground/vibecoding/deepseek-harness`)로 세션을 연다.
- 시작 전에 `git status --short studio/src`가 비어 있는지 본다. 남은 변경이 있으면 결과와 섞이므로 먼저 정리한다.

### 진행

1. `Test Preset`으로 새 세션을 연다.
2. 다음을 보낸다.

   ```text
   studio-ko-locale-review 스킬로 Pixie 로케일 한국어를 검토해 줘. 먼저 judge 결과와 고칠 안을 표로 보여 주고, 내가 승인한 줄만 고쳐.
   ```

3. 표가 나오면 몇 줄만 골라 승인한다. 일부는 일부러 승인하지 않는다.
4. 수정과 검사가 끝날 때까지 기다린다.

### 판정

| # | 항목 | 통과 기준 |
|---|---|---|
| 1-1 | 스킬 사용 | 에이전트가 `studio-ko-locale-review`를 불러왔다(세션 기록에 스킬 로드) |
| 1-2 | 판정 도구 사용 | 세션 기록에 `judge` 도구 호출이 있고 결과의 `engine`이 `jev` |
| 1-3 | 판정 형식 | 요청이 `{ state, questions }` 형식이고 질문 id가 규칙(`^[A-Za-z][A-Za-z0-9_-]*$`)을 지킨다 |
| 1-4 | 오류 처리 | 도구 오류가 있었다면 "판정 안 됨"으로 보고되고 교정 대상으로 섞이지 않았다 |
| 1-5 | 승인 전 무수정 | 표를 보여 주기 전과 승인 전에 로케일 파일이 바뀌지 않았다 |
| 1-6 | 승인 범위 | `git diff studio/src`에 승인한 줄만 있고, 키·영어·중국어·`{...}` 자리표시자·`Pixie`/`Jev`/`'pixie judge'`가 그대로다 |
| 1-7 | 백틱 없음 | 바뀐 한국어 문구에 백틱이 없다 |
| 1-8 | 검사 | 에이전트가 `npm --prefix studio run typecheck`와 `design-rules` 테스트를 돌렸고 통과했다(실패했다면 해당 수정을 되돌렸다) |
| 1-9 | 보고 | 판정 수, 교정 대상 수, 수정 수, 판정 안 된 수가 따로 나온다 |

### 정리

확인이 끝나면 수정을 남길지 정한다. 남기지 않으려면 `git checkout -- studio/src`로 되돌린다. 남기면 별도 커밋으로 둔다.

## 2. 영어 최종 답변을 한국어로 (답변 끝 게이트)

### 준비

- 스크립트: `~/.dsh/profiles/desktop/studio-data/pixie-gate/commands/translate-check.sh` (실행 권한 필요).
  1. 답변이 한국어인지 Jev로 판정한다(`--threshold 0.8`, 코드·경로·명령 출력 제외). 한국어면 exit 10.
  2. 아니면 Pixie가 번역한다(코드·경로·숫자·Markdown 구조 유지).
  3. 원문과 번역을 함께 Jev로 충실도 판정한다(`--threshold 0.7`). 번역은 최대 2번 시도한다.
  4. exit 11로 `[한국어 번역]` 메모를 남긴다. 끝까지 통과하지 못하면 `[한국어 번역 — 충실도 미확인]` 메모를 남긴다.
  5. 헬퍼 오류는 exit 1이다. 오류 정책이 통과라서 답변은 그대로 간다.
- 게이트: `#27 영어 답변 번역` (`turn-end`, 할 일 비움, 제한 시간 120초, 오류 시 통과, 대상 `Test Preset`). **게이트 → 게이트 구성**에서 켜져 있는지 본다.

### 진행

1. `Test Preset`으로 새 세션을 연다.
2. 영어 답변을 유도한다. 예: `Answer in English only: what does git rebase do? Include one command example.`
3. 답변이 끝나면 오른쪽 **Pixie 탭 → 게이트**에서 `#27 영어 답변 번역` 기록을 연다.
4. 같은 세션에서 한국어로 질문한다. 예: `git rebase가 뭔지 한국어로 두 문장으로 설명해 줘.`
5. 두 번째 기록을 연다.

### 판정

| # | 항목 | 통과 기준 |
|---|---|---|
| 2-1 | 영어 답변 번역 | 첫 기록의 결론이 `훅 스크립트`, **스크립트 출력 → 메모**에 `[한국어 번역]`으로 시작하는 한국어 번역이 있다 |
| 2-2 | 번역 품질 | 명령 예시와 코드가 원문 그대로이고, Markdown(목록·코드 블록)이 표시된다 |
| 2-3 | 판정 엔진 | **헬퍼 호출**에 `pixie-judge` 두 건 이상, `pixie-ask` 한 건 이상. 판정 줄에 `jev` |
| 2-4 | 한국어 답변 건너뜀 | 두 번째 기록의 결론이 `훅이 건너뜀`, 헬퍼 호출은 `pixie-judge` 한 건뿐 |
| 2-5 | 대화 영향 없음 | 대화창의 원래 답변이 그대로이고, 에이전트에게 교정 지시(steer)가 가지 않았다(적용: 없음 또는 메모만) |
| 2-6 | 시간 | 기록의 소요 시간이 제한 시간(120초) 안이다 |

알려진 한계: 대화창의 영어 답변은 접거나 바꿀 수 없다. 번역은 Pixie 탭의 게이트 기록에만 보인다.

## 3. 서브에이전트 라우팅 (도구 실행 전 게이트)

### 준비

**아직 만들지 않았다.** 스크립트와 게이트를 만든 뒤 진행한다.

- 동작
  - 메인 에이전트가 `subagent_role`(`action: call`, `role`, `task`)을 부르기 직전에 게이트가 실행된다.
  - 서브에이전트는 판정이 끝난 뒤에만 만들어진다.
  - 결정권은 메인 에이전트에 있다. 게이트는 그 결정을 평가해 통과 또는 거부만 한다. 호출 인자의 역할을 바꿔 넣을 수는 없다.
- 스크립트(예: `route-role.sh`)가 할 일
  1. `PIXIE_TOOL_NAME`이 `subagent_role`이 아니거나 `action`이 `call`이 아니면 exit 10.
  2. `PIXIE_TOOL_ARGS`에서 `role`과 `task`를 `jq`로 꺼낸다.
  3. `<프로필>/studio-data/presets.json`에서 `Test Preset`의 역할 목록(이름·모델·추론 강도)을 `jq`로 읽는다.
  4. 한 번의 판정에 질문 두 개를 묶는다.
     - noul: "이 작업을 `<role>`(모델, 추론)에게 맡기는 게 적절한가?"
     - choice: 역할 목록 중 가장 맞는 역할. 선택지 설명에는 역할마다 어떤 작업에 맞는지 적는다.
       - 예: Reviewer는 짧은 확인·검토, Researcher는 여러 자료 조사·깊은 추론, Worker는 코드 구현.
  5. 적합 확률이 기준값(0.5) 이상이거나 choice 확신도가 낮으면(0.6 미만) exit 10.
  6. 아니면 exit 11 `{"verdict":"stop","reason":"이 작업은 <추천 역할>이 맞습니다. role을 <추천 역할>로 다시 호출하세요."}`.
  7. 헬퍼 오류는 exit 1이다(오류 시 통과).
- 게이트: 지점 `tool-before`, 할 일 비움, 오류 시 통과, 대상 `Test Preset`, 대상 에이전트 `root`.

### 진행

1. `Test Preset`으로 새 세션을 연다.
2. 역할이 맞지 않게 위임을 유도한다. 예: `subagent_role로 Reviewer에게 맡겨: DSH 저장소에서 credentials 저장 방식이 파일·환경 변수·.env를 어떤 순서로 읽는지 코드를 찾아 정리해 줘.`
3. 역할이 맞게 위임을 유도한다. 예: `subagent_role로 Reviewer에게 맡겨: studio/README.md 첫 단락에 오타가 있는지 확인만 해 줘.`
4. 각 위임 뒤 Pixie 탭 게이트 기록과 세션 기록(서브에이전트 시작 여부)을 본다.

### 판정

| # | 항목 | 통과 기준 |
|---|---|---|
| 3-1 | 다른 도구 무영향 | `read`·`bash` 등 다른 도구 호출의 게이트 기록이 `훅이 건너뜀`이고 Jev 호출이 없다 |
| 3-2 | 맞지 않는 역할 거부 | 2번 위임의 첫 호출 기록이 `적용: 거부`, 결론 `훅 스크립트`, 이유에 추천 역할이 있다 |
| 3-3 | 거부 시 서브에이전트 없음 | 거부된 호출에 대응하는 서브에이전트 세션이 없다 |
| 3-4 | 재호출 | 메인 에이전트가 추천 역할로 다시 호출했고, 그 기록은 통과이며 서브에이전트가 시작됐다 |
| 3-5 | 맞는 역할 통과 | 3번 위임은 바로 통과하고 서브에이전트가 시작됐다 |
| 3-6 | 판정 기록 | **헬퍼 호출**에 bool 확률과 `select → <역할> · jev · 확신도 n%`가 남았다 |
| 3-7 | 반복 없음 | 같은 위임이 두 번 넘게 거부되지 않았다. 거부가 반복되면 기준값이나 선택지 설명을 조정한다 |

알려진 한계: 세 역할 중 둘이 같은 모델(deepseek-flash)이라 실제 비용 차이는 Worker 쪽에서만 크다. 라우팅이 맞았는지는 게이트 기록의 판정으로 본다.

## 보고 양식

```markdown
## Jev 결정 엔진 실사용 확인 결과 (<날짜>)

- DSH: <버전>, Studio 설치 <시각>, 앱 시작 <시각>
- 결정 엔진: <Jev / LLM>, 키 출처: <file / env>
- 프리셋: Test Preset (studio-user-da0ba041-…)

| # | 항목 | 판정 | 근거 (세션 ID, 기록 내용, diff) |
|---|---|---|---|
| 1-1 | 스킬 사용 | 통과/실패/확인 불가 | … |
| … | … | … | … |

### 차이와 이상
- <실패·확인 불가 항목의 실제 값, 오류 문구, 예상과 다른 판정 확률>

### 조정한 값
- <기준값·질문 문구·선택지 설명을 바꿨다면 전후 값>

### 실행하지 않은 것
- <생략한 상황·단계와 이유>
```

확인하지 못한 항목을 통과로 적지 않는다. 판정 확률은 그대로 적는다. Jev 판정은 한국어에서 신호이지 보증이 아니다.
