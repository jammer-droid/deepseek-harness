# Jev 결정 엔진 실사용 확인 (#27): 로케일 교정과 영어 답변 번역

> fork 내부 확인용이다. 공개 안내는 [Pixie Gate 가이드](../../release/docs/appendix/pixie-gate.ko.md)를 따른다. 서브에이전트 라우팅(3번)은 스크립트와 게이트를 만든 뒤 이 문서에 추가한다.

이 문서를 받은 에이전트는 아래 순서대로 두 가지를 진행하고 결과를 세션에 보고한다. 사용자가 **Test Preset**으로 연 세션에서 이 문서를 읽으라고 지시한 상태를 전제로 한다. 사용자는 결과를 세션 창과 오른쪽 Pixie 탭에서 확인한다.

| # | 상황 | 판정하는 쪽 | 행동하는 쪽 |
|---|---|---|---|
| 1 | Pixie·결정 엔진 로케일 한국어 교정 | 에이전트가 부르는 `judge` 도구(Jev) | 에이전트가 고칠 안을 만들고, 사용자 승인 뒤 수정 |
| 2 | 영어 최종 답변을 한국어로 | 답변 끝 게이트 스크립트의 `pixie judge`(Jev) | Pixie가 번역하고 스크립트가 메모를 남김(자동) |

## 지켜야 할 범위

- 파일 수정은 1번에서 사용자가 승인한 로케일 문구로만 한정한다. 대상은 `studio/src/pixie-locale.ts`(Pixie 탭·스레드·설정·결정 엔진 화면)와 `studio/src/pixie-gate-judge-locale.ts`(실행 기록의 판정 표시) 두 파일뿐이다. 게이트 구성·편집기·실행 기록 문구 파일(`pixie-gate-locale.ts`, `pixie-gate-task-locale.ts`, `pixie-gate-compose-locale.ts`, `pixie-gate-editor-locale.ts`)은 판정도 수정도 하지 않는다. 프리셋, 게이트, 스크립트, 스킬, Studio 설정, 다른 소스는 바꾸지 않는다.
- 사용자 승인이 필요한 단계에서는 멈추고 묻는다. 승인을 추측하지 않는다.
- 커밋하지 않는다.
- Jev로 보내는 텍스트(로케일 문구, 판정할 답변)는 TypeSafe로 전송된다. 1번 시작 전에 이 점을 사용자에게 한 줄로 알린다.

## 0. 시작 확인

다음을 확인하고 한 표로 보고한다. 하나라도 맞지 않으면 그 항목을 적고 멈춘다.

1. 사용 가능한 도구에 `judge`, `read`, `edit`, `bash`가 있다.
2. 스킬 목록에 `studio-ko-locale-review`가 있다.
3. 작업 디렉터리가 DSH 저장소 루트이고, `git status --short studio/src` 결과가 비어 있다. 비어 있지 않으면 목록을 보여 주고 사용자에게 진행 여부를 묻는다.
4. `judge`를 한 번 호출해 엔진을 확인한다. 아래 요청을 그대로 쓴다. 결과의 `engine`이 `jev`여야 한다.

   ```json
   { "state": "키를 저장했습니다.", "questions": { "polite": { "type": "noul", "instructions": "Does this Korean UI text use the formal polite ending (합쇼체)?" } } }
   ```

   도구 오류가 나면 오류 문구를 그대로 보고하고 멈춘다. 엔진이 `llm`이면 사용자에게 알리고 계속할지 묻는다.

## 1. Pixie·결정 엔진 로케일 한국어 교정

1. `studio-ko-locale-review` 스킬을 불러와 그 절차를 따른다. 이 문서와 스킬이 충돌하면 스킬의 범위·기준값을 따르고, 충돌 내용을 보고에 적는다.
2. 판정이 끝나면 스킬의 표를 보여 주고 **멈춘다.** 사용자가 승인할 줄을 정할 때까지 파일을 고치지 않는다.
3. 사용자가 승인한 줄만 고치고, 스킬에 적힌 검사를 실행한다.
4. 아래 판정 표를 채워 보고한다.

| # | 항목 | 통과 기준 |
|---|---|---|
| 1-1 | 스킬 사용 | `studio-ko-locale-review`를 불러왔다 |
| 1-1b | 대상 파일 | 판정 요청에 들어간 문구가 위 두 파일의 것뿐이다 |
| 1-2 | 판정 도구 사용 | `judge` 호출 결과의 `engine`이 `jev`. 호출 수를 적는다 |
| 1-3 | 판정 형식 | 요청이 `{ state, questions }` 형식이고 질문 id가 `^[A-Za-z][A-Za-z0-9_-]*$`를 지킨다 |
| 1-4 | 오류 처리 | 도구 오류는 "판정 안 됨"으로 따로 셌고 교정 대상에 섞지 않았다(오류가 없으면 "해당 없음") |
| 1-5 | 승인 전 무수정 | 표를 보여 준 뒤 승인 전까지 `git status --short studio/src`가 비어 있었다 |
| 1-6 | 승인 범위 | `git diff studio/src`에 위 두 파일의 승인한 줄만 있고, 키·영어·중국어·`{...}` 자리표시자·`Pixie`/`Jev`/`'pixie judge'`가 그대로다 |
| 1-7 | 백틱 없음 | 바뀐 한국어 문구에 백틱이 없다 |
| 1-8 | 검사 | 타입 검사와 `design-rules` 테스트가 통과했다. 실패했다면 해당 수정을 되돌렸다 |
| 1-9 | 집계 | 판정 수, 교정 대상 수, 수정 수, 판정 안 된 수가 따로 나온다 |

`git diff --stat studio/src`와 바뀐 줄의 전후 문구를 함께 보여 준다. 수정은 커밋하지 않는다. 남길지는 사용자가 정한다.

## 2. 영어 최종 답변을 한국어로

이 단계는 **에이전트 자신의 답변이 끝날 때** 게이트가 실행된다. 에이전트는 게이트 결과를 같은 턴에 볼 수 없으므로, 확인은 사용자가 Pixie 탭에서 하고 에이전트는 다음 턴에 기록 파일로 다시 확인한다.

설정(바꾸지 않는다):
- 게이트 `#27 영어 답변 번역`(`turn-end`, 대상 Test Preset, 할 일 비움, 제한 시간 120초, 오류 시 통과)
- 스크립트 `~/.dsh/profiles/desktop/studio-data/pixie-gate/commands/translate-check.sh`
  1. 답변이 한국어면(Jev, 기준 0.8) 건너뛴다.
  2. 아니면 Pixie가 번역하고 Jev가 원문과 비교해 충실도를 판정한다(기준 0.7, 최대 2회).
  3. `[한국어 번역]` 메모를 남긴다. 충실도를 통과하지 못하면 `[한국어 번역 — 충실도 미확인]` 메모를 남긴다.

### 진행

1. 1번 보고를 마친 뒤, 사용자에게 "다음 답변을 영어로 하겠습니다. 답변이 끝나면 Pixie 탭 → 게이트에서 `#27 영어 답변 번역` 기록을 확인해 주세요"라고 알린다.
2. **다음 답변 전체를 영어로만** 쓴다. 내용은 `git rebase`가 무엇인지 3–4문장, 명령 예시 코드 블록 하나, 짧은 목록 하나다. 이 답변에는 한국어를 섞지 않고 도구를 부르지 않는다.
3. 사용자가 다음 메시지를 보내면, 그 메시지를 한국어로 답하기 전에 기록 파일을 읽어 확인한다.
   - 위치: `~/.dsh/profiles/desktop/studio-data/pixie/gates/session-<현재 세션 ID>.json`
   - `gateName`이 `#27 영어 답변 번역`인 실행 중 가장 최근 것을 본다.
   - 세션 ID를 모르면 `ls -t` 결과에서 가장 최근 파일을 쓰고, 그렇게 찾았다고 보고에 적는다.
4. 그 턴의 답변은 **한국어로** 쓴다. 이 답변이 끝나면 게이트가 다시 실행되고 건너뛰어야 한다. 사용자가 한 번 더 메시지를 보내면 같은 파일에서 두 번째 기록을 확인한다.
5. 아래 판정 표를 채워 보고한다.

| # | 항목 | 통과 기준 (기록 파일 필드) |
|---|---|---|
| 2-1 | 영어 답변 번역 | 영어 답변 기록의 `result.concludedBy`가 `script`, `output.note`가 `[한국어 번역]`으로 시작하고 한국어다 |
| 2-2 | 번역 품질 | 메모 안의 명령 예시·코드가 원문과 같고 Markdown 구조(코드 블록·목록)가 남아 있다 |
| 2-3 | 판정 엔진 | `result.records`에 `pixie-judge` 두 건 이상과 `pixie-ask` 한 건 이상. 판정 기록의 `data.engine`이 `jev` |
| 2-4 | 한국어 답변 건너뜀 | 한국어 답변 기록의 `result.concludedBy`가 `skipped`이고 `pixie-judge` 기록이 한 건뿐 |
| 2-5 | 대화 영향 없음 | 두 기록의 `applied`가 `none`. 교정 지시(steer)가 오지 않았다 |
| 2-7 | 대화창 번역 블록 | 사용자 확인: 영어 답변 바로 아래에 `한국어 번역` 블록이 보이고 Markdown(코드 블록·목록)으로 그려진다. 한국어 답변 아래에는 블록이 없다 |
| 2-8 | 세션 끄기 | 사용자 확인: 블록의 **이 세션에서 끄기**를 누른 뒤 보낸 영어 답변에는 새 기록과 블록이 없다. **Pixie 탭 → 게이트 → 이 세션의 게이트**에서 다시 켜면 다음 영어 답변부터 다시 번역된다 |
| 2-6 | 시간 | 두 기록의 `endedAt - startedAt`이 120,000ms 미만 |

판정 확률(bool 판정 기록의 `data.noul`, `data.threshold`)과 번역 메모 전문을 보고에 그대로 붙인다. 사용자가 Pixie 탭에서 본 내용과 기록 파일이 다르면 둘 다 적는다.

알려진 한계: 대화창의 영어 답변은 접거나 바꿀 수 없다. 번역은 답변 아래 블록과 Pixie 탭 게이트 기록에 보인다. 번역이 끝난 뒤에만 블록이 나타난다(진행 중 표시 없음). 2-7·2-8은 화면 확인이라 사용자에게 결과를 물어 적는다.

## 보고 양식

```markdown
## Jev 결정 엔진 실사용 확인 결과 (<날짜>)

- 세션: <세션 ID> (찾은 방법: <직접 확인 / 최근 파일>)
- 프리셋: Test Preset, 엔진: <jev / llm>, 시작 확인: <0단계 결과 요약>

| # | 항목 | 판정 | 근거 |
|---|---|---|---|
| 1-1 | 스킬 사용 | 통과/실패/확인 불가/해당 없음 | … |
| … | … | … | … |
| 2-6 | 시간 | … | … |

### 차이와 이상
- <실패·확인 불가 항목의 실제 값, 오류 문구, 예상과 다른 판정 확률>

### 실행하지 않은 것
- <생략한 단계와 이유>
```

확인하지 못한 항목을 통과로 적지 않는다. Jev 판정은 한국어에서 신호이지 보증이 아니다.
