# Studio 0.6.2 배포 E2E 검증

이 문서를 받은 에이전트(**검증자**)는 아래 단계를 순서대로 실행하고 보고 양식으로 결과를 낸다. 제품을 고치지 않는다. 판정 단계·올림 규칙·기다리기는 [에이전트 E2E 검증 지침](../../README.md#판정-단계)을 따른다.

배경: 0.6.2에는 #32(실행 기본값 화면), #33(세션 역할 Fresh/Fork 편집), #34(Optimized 튜닝·Worker 역할·편집과 기본값 복구·스키마 없는 Config 잠금)가 들어간다. 마지막 공개 버전은 0.6.1이다. #32·#33은 이슈 단계에서 격리 설치 검증을 마쳤으므로 smoke·RPC 수준으로 줄인다. 지원 DSH 버전(peer)은 0.6.1과 같으므로 matrix는 하지 않는다.

## 범위

- 대상: [CHANGELOG 0.6.2](../../../../release/CHANGELOG.md), [#34 명세](../../../../docs/issues/34-optimized-worker-tuning.md), [#34 이슈 지침서](../issues/34-optimized-worker-tuning.md). 대상 커밋은 0단계에서 기록한 `HEAD`, 런타임 `dsh 0.2.1-rc.2`(수정하지 않은 설치본).
- 쓰는 위치: `studio/dist/e2e/0.6.2/`와 하네스 기본 경로(`studio/dist/e2e/home`, `studio/dist/e2e/shots/`, `studio/dist/e2e/packs/`). tracked 파일·사용자 프로필은 바꾸지 않고 커밋·푸시·배포·이슈 변경은 하지 않는다.
- 외부 전송: 에이전트 제어는 각본 모델(`--mock-llm`, 토큰 0)이다. 화면 문구 판정을 L1로 올리면 그 문구가 Pixie 제공자·결정 엔진으로 전송된다.
- 비밀값: 없음.

## 0. 시작 확인

1. `git status --short`, `git branch --show-current`, `git log --oneline -5`를 기록한다.
2. `studio/packages/shell/package.json`의 `version`과 `src/package-name.ts`의 `STUDIO_VERSION`이 `0.6.2`이고, `release/CHANGELOG.md` 맨 위 섹션이 `## 0.6.2`인지 확인한다. 아니면 1~4단계는 `대기`다.
3. `dsh --version`이 `0.2.1-rc.2`인지 확인한다. 다르면 1~4단계는 `대기`다.
4. 도구 확인: PATH의 `zstd`, Playwright 모듈·Chrome. 없으면 해당 단계는 `환경 차단`이며 자동 설치하지 않는다([사전 조건](../../README.md#브라우저-검사-l0)).
5. `npm --prefix studio test`의 종료 코드와 테스트 수를 기록한다. workspace 회귀일 뿐 배포 증거가 아니다.

## 1. 신규 설치 (L0)

```sh
node studio/scripts/e2e/server.mjs up --mock-llm
```

`package`·`sha256`을 기록한다. 이 tarball을 이후 단계에서 그대로 쓴다(`studio/dist/e2e/packs/`에 복사해 경로를 기록한다).

| 단계 | 명령 | 기준선 | 올림 조건 |
| --- | --- | --- | --- |
| 기본 | `node studio/scripts/e2e/smoke.mjs` | 12/12, pageerror 0, 플러그인 실패 0 | 셀렉터 실패 → L1 셀렉터 복구 |
| #34 Optimized·Worker | `node studio/scripts/e2e/agent-optimized-worker.mjs` | 16/16 | 불일치 → L2 결함 후보 |

| #33 세션 역할 시작 방식 | `node studio/scripts/e2e/agent-session-role-spawn.mjs` | 모든 검사 통과 | 불일치 → L2 결함 후보 |
| Web RPC | `STUDIO_TEST_ISOLATED=1 STUDIO_TEST_PORT=<port> node studio/scripts/check-web-runtime.mjs '<url>'` | 네 스크립트 통과, Optimized 도구 27 | 실패 → L2 결함 후보 |

## 2. 화면 확인 (L0, 사람 확인 대체 아님)

[브라우저 기능 확인](../../README.md#브라우저-기능-확인) 1~7 중 아래를 확인한다. 셀렉터는 [browser.mjs](../../../e2e/browser.mjs)의 `app.step()`을 쓴다. 스크린샷은 `studio/dist/e2e/shots/0.6.2-*.png`로 남긴다.

- 프리셋 목록: Master 읽기 전용, Optimized 카드의 `편집` 활성·`삭제` 비활성·`기본값으로 복구` 있음, 설명 문구가 Worker 역할을 언급.
- Optimized 편집 → 프롬프트 내용 한 줄 수정 → 저장: 카드에 `직접 편집함`. `기본값으로 복구` → 확인 창 → `복구하고 반영`: `직접 편집함`이 사라지고 `반영됨`.
- 편집 → 실행 설정: 실행 기본값에 bash 120000. Config에서 `여러 파일 한 번에 읽기`는 켜진 채 잠김과 안내 문구, `한 파일 여러 곳 고치기`는 꺼진 채 "스키마를 읽을 수 없어 편집할 수 없습니다.".
- 서브에이전트 탭: Worker 역할 1개.
- 라이트·다크, 480px 폭에서 프리셋 목록과 Config 화면. 콘솔 오류 0.

## 3. 업그레이드 (L0)

0.6.1에서 올리는 사용자의 Optimized가 새 기본값으로 바뀌는지, 복사본은 그대로인지 확인한다([업그레이드 검사](../../README.md#업그레이드-검사)).

1. `node studio/scripts/e2e/server.mjs down` 후 0.6.1을 받는다.

   ```sh
   npm pack @matamt-dbg/dsh-studio@0.6.1 --pack-destination studio/dist/e2e/packs
   node studio/scripts/e2e/server.mjs up --profile upgrade --archive "$PWD/studio/dist/e2e/packs/matamt-dbg-dsh-studio-0.6.1.tgz"
   ```

2. RPC로 기록한다: Optimized의 `request.tools.length`(기준 22), bash 실행 기본값(600000), `agents.length`(0), `status`(`applied`). Optimized의 `id`를 뺀 내용을 이름 `__upgrade_copy__`로 `studioCatalog/savePreset`에 저장하고 `studioCatalog/applyPreset`으로 반영한다(RPC 호출 형식은 [agent.mjs](../../../e2e/agent.mjs)의 `rpc()`를 참고한다).
3. 같은 프로필에 후보를 올린다.

   ```sh
   node studio/scripts/e2e/server.mjs down --profile upgrade
   node studio/scripts/e2e/server.mjs up --profile upgrade --reuse-profile --archive <1단계 tgz 절대 경로>
   ```

4. 기대값: Optimized는 도구 27, bash 120000, Worker 1개, `status` `applied`, `customized` 없음. `__upgrade_copy__`는 도구 22, bash 600000, 역할 0으로 그대로이고 `applied`다.
5. `smoke.mjs --profile upgrade`가 통과하고, 서버 로그에 Studio 플러그인 실패가 없다.
6. `down --profile upgrade`.

## 4. 정리

```sh
node studio/scripts/e2e/server.mjs down
```

`portFree: true`를 기록한다. 결론으로 남길 기록은 메인 세션이 `studio/docs/verification/`과 CHANGELOG 검증 노트에 옮긴다.
