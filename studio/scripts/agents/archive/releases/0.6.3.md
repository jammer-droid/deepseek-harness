# Studio 0.6.3 배포 E2E 검증

이 문서를 받은 에이전트(**검증자**)는 아래 단계를 순서대로 실행하고 보고 양식으로 결과를 낸다. 제품을 고치지 않는다. 판정 단계·올림 규칙·기다리기는 [에이전트 E2E 검증 지침](../../README.md#판정-단계)을 따른다.

배경: 0.6.3에는 #38(설치한 플러그인 자동 감지, 실행 범위 구분, 프로필 공용 설정, 워크플로우 카테고리, 공급자 직접 입력)이 들어간다. 마지막 공개 버전은 0.6.2다. #38은 이슈 단계에서 수정하지 않은 DSH `0.2.1-rc.2` 격리 설치로 S1–S13을 확인했으므로, 여기서는 배포 후보 패키지로 핵심 흐름과 회귀만 다시 본다.

## 범위

- 대상: [CHANGELOG 0.6.3](../../../../release/CHANGELOG.md), [#38 명세](../../../../docs/issues/38-installed-plugins.md). 대상 커밋은 0단계에서 기록한 `HEAD`, 런타임 `dsh 0.2.1-rc.2`(수정하지 않은 설치본).
- 쓰는 위치: `studio/dist/e2e/0.6.3/`와 하네스 기본 경로(`studio/dist/e2e/home`, `studio/dist/e2e/shots/`, `studio/dist/e2e/packs/`). tracked 파일·사용자 프로필(`~/.dsh`)은 바꾸지 않고 커밋·푸시·배포·이슈 변경은 하지 않는다.
- 외부 전송: 없음. 에이전트 제어는 각본 모델(`--mock-llm`, 토큰 0)이고, Exa 검색은 로컬 가짜 엔드포인트로 대신한다. 화면 문구 판정을 L1로 올리면 그 문구가 Pixie 제공자·결정 엔진으로 전송된다.
- 비밀값: 없음. 가짜 엔드포인트에 쓰는 키는 임의 문자열(`fake-release-key`)이다.

## 0. 시작 확인

1. `git status --short`, `git branch --show-current`, `git log --oneline -5`를 기록한다.
2. `studio/packages/shell/package.json`의 `version`과 `studio/src/package-name.ts`의 `STUDIO_VERSION`이 `0.6.3`이고, `studio/release/CHANGELOG.md` 맨 위 섹션이 `## 0.6.3`인지 확인한다. 아니면 1~4단계는 `대기`다.
3. `dsh --version`이 `0.2.1-rc.2`인지 확인한다. 다르면 1~4단계는 `대기`다.
4. 도구 확인: PATH의 `zstd`, Playwright 모듈·Chrome. 없으면 해당 단계는 `환경 차단`이며 자동 설치하지 않는다([사전 조건](../../README.md#브라우저-검사-l0)).
5. `npm --prefix studio test`의 종료 코드와 테스트 수를 기록한다. workspace 회귀일 뿐 배포 증거가 아니다.
6. 모든 명령 전에 `export STUDIO_E2E_PROFILE=r063`을 둔다.

## 1. 신규 설치와 회귀 (L0)

```sh
node studio/scripts/e2e/server.mjs up --mock-llm --plugin @deepseek-ai/dsh-web-search-exa@0.2.1-rc.2
```

`package`·`sha256`을 기록하고 tarball을 `studio/dist/e2e/0.6.3/`에 복사한다. 이후 단계는 이 패키지만 쓴다(`--archive <경로>`).

| 단계 | 명령 | 기준선 | 올림 조건 |
| --- | --- | --- | --- |
| 기본 | `node studio/scripts/e2e/smoke.mjs` | 모든 검사 통과, pageerror 0, 플러그인 실패 0 | 셀렉터 실패 → L1 셀렉터 복구 |
| Web RPC 회귀 | `STUDIO_TEST_ISOLATED=1 STUDIO_TEST_PORT=<port> node studio/scripts/check-web-runtime.mjs '<url>'` | 네 스크립트 통과 | 실패 → L2 결함 후보 |
| Optimized·Worker 회귀 | `node studio/scripts/e2e/agent-optimized-worker.mjs` | 모든 검사 통과 | 불일치 → L2 결함 후보 |

## 2. #38 흐름 (L0)

RPC는 [s38-repro.mjs](../../../e2e/s38-repro.mjs)와 같은 방식(상태 파일의 URL·쿠키로 `/api/studioCatalog/<method>` 호출)으로 작은 스크립트를 `studio/dist/e2e/0.6.3/`에 써서 호출한다. 결과 JSON을 기록한다.

| 단계 | 행동 | 기대 |
| --- | --- | --- |
| R1 분류 | `listInstalledPlugins` | Exa 행 `scope: profile`, `state: installed` |
| R2 차단 | `addMasterPlugin` `@deepseek-ai/dsh-web-search-exa` | 거부, 메시지에 `Host service shared by every session`. 이어서 `listPresets`에서 Optimized `applied`, 경고 없음 |
| R3 등록 | `registerProfilePlugin` `{"entry":"@deepseek-ai/dsh-web-search-exa"}` | `id: web-search-exa`. 재호출은 거부. 프로필 `cordis.patch.yml`에 insert 한 항목만 추가 |
| R4 설정 | 가짜 Exa 엔드포인트를 `127.0.0.1`의 빈 포트에 띄운다(POST `/search`에 `results: [{ url, title, highlights: ['R063_SNIPPET'] }]`를 돌려주고 `authorization` 헤더를 기록). `saveProfileConfig`로 `web-search-exa`에 `baseURL`과 `apiKey` 교체(`fake-release-key`), `web`에 `searchProvider: exa` | `listProfileConfigs` 응답에 `fake-release-key`가 없고 `apiKey` `set: true` |
| R5 검색 | `agent.mjs`의 `runAgent`로 `web_search`만 고른 프리셋에서 `MOCK tool web_search {"queries":["r063"]}` 실행 | 세션에 `R063_SNIPPET`, 가짜 엔드포인트에 `Bearer fake-release-key` |
| R6 기본값 | `saveProfileConfig` `web`에 `diff: {}` | patch에서 `web` 덮어쓰기 행 제거 |
| R7 재시작 | `server.mjs down` 후 `up --skip-build --reuse-profile --archive <같은 tgz>` | Master·Optimized `applied`, `listProfileConfigs`에 7개 카테고리의 행(웹·위임 공급자·루프 가드·목표·컨텍스트·MCP·모델) |

가짜 엔드포인트는 끝나면 종료하고 포트가 비었는지 기록한다.

## 3. 업그레이드 (L0)

0.6.2에서 Exa를 Master에 추가해 둔 프로필이 0.6.3으로 올라가는 경로다.

1. `export STUDIO_E2E_PROFILE=r063up`, `node studio/scripts/e2e/server.mjs up --mock-llm --archive <0.6.2 tgz> --plugin @deepseek-ai/dsh-web-search-exa@0.2.1-rc.2`. 0.6.2 tgz는 npm `@matamt-dbg/dsh-studio@0.6.2`를 `npm pack`으로 `studio/dist/e2e/0.6.3/`에 받는다. 받을 수 없으면 이 단계는 `환경 차단`이다.
2. `addMasterPlugin`으로 Exa를 추가한다(0.6.2는 허용).
3. `server.mjs down` 후 `up --skip-build --reuse-profile --archive <0.6.3 tgz>`로 올린다.
4. `extensionMigration`: Exa 한 건, `config`의 비밀은 표식만. `migrateExtension`: 성공, `studio-data/migrated-extensions.json` 권한 600. 이후 `listInstalledPlugins`의 Exa `pendingPresets`가 비어 있거나 반영 프리셋 이름을 담는다. 비어 있지 않으면 해당 프리셋을 `applyPreset` 한 뒤 다시 확인한다.
5. Optimized `applyPreset`이 성공한다.
