# 0.6.6 DSH rc.3 호환성 배포 검증

제품을 수정하지 않는 검증자용 지침이다. 공통 절차는 [E2E 검증 지침](../../README.md), 대응 기준은 [호환성 오류 대응](../../../../docs/development/dsh-compatibility-response.md)을 따른다.

## 범위와 시작 확인

- 소스 기준: `9deeac2d91`, Studio `0.6.6`, 별도 Exa fetch `0.1.2`. Subscriptions는 원본 공개 배포가 아닌 로컬 포크 `0.9.9-local.rc3.1`이다.
- 런타임: 수정하지 않은 DSH `0.2.1-rc.3` 배포 CLI. 실행 경로와 `--version`을 기록한다.
- 산출물은 `studio/dist/rc3-compat/` 아래에만 쓴다. 사용자 프로필·인증 저장소·tracked 제품 파일은 수정하지 않는다. 실제 모델·Exa 요청 비용과 비밀값 복사는 없다.
- 각본 모델을 쓰며 `zstd` 등 준비물이 없으면 환경 차단으로 기록한다. 브라우저 도구 정책이 저장소 Playwright 하네스보다 우선하면 CUA를 사용하고 검사 방법을 구분한다.

## L0 실행

1. 공개 의존성으로 만든 Studio 후보 tgz의 SHA1·SHA256을 기록한다. 같은 파일에 대해 새 home·`rc3-public` 프로필을 만든다. 모든 명령에 `STUDIO_E2E_HOME`과 `STUDIO_E2E_PROFILE`을 명시한다.
2. `server.mjs up --archive <Studio tgz> --mock-llm --plugin <Exa tgz> --plugin <Subscriptions tgz>`를 실행한다. 설치·기동 실패와 경고를 구분한다. 인증 URL은 출력·보고서에 노출하지 않는다.
3. state의 인증 URL과 포트로 `check-web-runtime.mjs`를 실행한다. `STUDIO_TEST_ISOLATED=1`과 `STUDIO_TEST_PORT`를 정확히 지정한다. 기대값은 RPC 4개 통과다.
4. `agent-roles.mjs`와 `agent-optimized-worker.mjs`를 실행한다. 전자는 5개(역할 persona·금지 도구·부모 상속·격리), 후자는 16개(Optimized·Worker) 검사를 기대한다. cold resume 통과로 해석하지 않는다.
5. 설치된 패키지 파일을 각 tgz와 대조한다. 새 프로필에서 Studio·Pixie·Subscriptions 화면, Exa 활성화, 좁은 폭의 More conversation views → Subagents를 확인한다.
6. npm 공개 뒤 레지스트리에서 다시 받은 tgz와 게시한 해시가 같은지 확인하고 격리 프로필에 설치한다. 원시 결과는 버전별 검증 문서와 구분한다.

## 판정과 정리

- 코드로 정해지는 사실은 L0에서 판정한다. `pixie_loop`·`judge` 도구가 없으면 L1은 환경 차단으로 기록하고 독립 수동 검토 여부를 별도로 적는다.
- 실모델 응답·실제 Exa API·cold resume·다른 DSH 버전은 이번 시나리오의 통과 항목이 아니다. 과거 버전 기록으로 이번 실행을 대신하지 않는다.
- main에 GUI 확인을 넘길 때는 서버를 유지하고 프로필·포트·상태 파일만 전달한다. 최종 확인 뒤 이 작업의 서버만 `server.mjs down`으로 종료하고 `portFree: true`를 확인한다.
- 결과에는 runtime·tarball hash·검사 수·실패·미실행·환경 차단·산출물 위치를 기록한다. 최종 기록은 [rc.3 검증](../../../../docs/verification/dsh-0.2.1-rc.3.md)에 반영한다.
