# 领域文档

[English](domain.md) | 中文

本仓库使用同一份共享领域上下文。术语和决策由现有文档负责；不要另建术语表或 ADR 目录树。

## 探索之前

处理 Studio 工作时，先阅读[产品目标与范围](../../studio/goals.ko.md)和[开发指南](../../studio/development.ko.md)。产品目标不代表已交付的行为；实现候选方案在获批前仍是提案。

先阅读[共享术语表](../glossary.zh.md)，再阅读 `.agents/notes/` 下相关的有效 Agent Notes。使用 [Agent Note 指南](../../.agents/notes/README.zh.md)按生命周期和类别查找记录。

已实现的记录描述已交付的决策。提案记录不代表已采纳的决策。被否决的记录保留不采用某种方案的理由。归档记录是冻结的历史资料，不能作为当前依据。

如果可选的领域文档不存在，继续工作，不要仅为了满足 skill 的默认目录布局而要求创建它。

## 术语

在 issue、提案、测试和说明中使用术语表的规范用词。当所需概念不存在时，区分真正的术语缺口与不必要的同义词。

## 决策冲突

明确指出与有效决策记录冲突的提案。链接该记录，并解释为何有必要重新讨论该决策；不要默默覆盖它。

## 编写领域文档

更新现有术语表，不要在根目录添加 `GLOSSARY.md` 或 `GLOSSARY-MAP.md`。通过现有 Agent Note 流程记录长期有效的决策理由，不要创建 `docs/adr/`。

遵循仓库的文档、双语配对和 Agent Note 创建规则。
